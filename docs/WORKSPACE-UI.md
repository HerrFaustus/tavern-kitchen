# 酒馆后厨工作台界面约定

工作台沿用宿主右侧抽屉的桌面尺寸和主题。剧情规划使用酒馆的下拉框、文本框和按钮，札记发布失败时在状态旁显示重试。运行 `node scripts/check-planner-ui.mjs` 可在独立无头浏览器中对照角色抽屉，验证三种宽度、保存回调和重试入口。脚本默认使用 Windows Edge 和工作区的酒馆参考源码，也可通过 `CHROMIUM_BIN` 指定 Chromium 可执行文件，通过 `SILLYTAVERN_PUBLIC` 指定酒馆的 public 目录。

当前剧情不再维护独立的「场景」记录或完整在场名单。正文续写沿用最近原文和剧情总结，地图和人物提供已确认的位置，人物在场度和认知按各自依据更新。同区域用于近景演化；目击和知情仍需要正文证据。旧场景保留在需要校验的历史回执中，不进入活动剧情状态。

「世界 → 地图」有地点列表、区域地图，以及有要素时可打开的局部地图。列表按世界、地区、地点、地点要素展开；选中名称可看详情，点箭头可折叠。旧地图缺少归属的记录暂列在“待归属”，具体建筑、房间的原始路径在详情保留。区域图显示当前范围内有记录的连接、方向和主角位置，优先采用已有位置或明确的方位。点图、列表或路线只切换浏览对象。“回到当前位置”定位到主角。世界、地区、地点可记录概述、边界、空间格局、功能、地貌、日常、习俗、历史、通行和感官印象；要素可记录外观、位置、用途、痕迹和状态。全景和详情中能唯一对应的地点名、本地要素名可以点开。局部地图以地点或同地要素为参照，按明确记载的八方方位显示要素；方位未知的条目列在“方位待定”。独立更新按材料逐项补录，正文按原字符预算取当前和相关资料。运行 `node scripts/check-place-map.mjs` 可用无头浏览器验证四层折叠、详情、单向通道及两种视图的联动。
地图详情从全景读到「此刻」和可点击要素。「此刻」从当前分支读取仍生效且有明确范围的风物、见闻及事态的当地影响。地区范围覆盖其下地点，同名地无法消歧时不展示。结束后该段自动撤下，世界与地图共用一份局势记录。地图长期保存地方常态和已确认的永久变化。资料充足时，全景按层级约50–450字，近景专项80–180字、重要要素描述80–160字，单项文本上限1200字；正文仍按既有800字符地图预算筛选。无头验收使用 `node scripts/check-place-map.mjs`，覆盖平日、节中、节后重访。


### 正文收到的资料

剧情记忆直接发送当前相关状态、有楼层范围的早期总结和带楼层、说话人的召回原文。旧记忆模板和首尾包裹词停止生效。世界资料保留当前事实、人物认知和幕后动态的区别；地图标注到访情况。管理员专用字段使用「管理员私有/属性名」，只在独立更新的完整世界快照里读取。旧聊天里已经写进正文或总结的文字保留原样。
街头见闻由「世界 → 局势 → 风物」管理。运行 `node --import tsx --test scripts/kitchen.test.mjs modules/story-state/ambient.test.js modules/world-records/authority.test.js modules/story-summary/tests/recall-reuse.test.js` 检查这些注入边界。

### 人物何时建档

- 一次叫卖、围观或擦肩而过，有叙事价值就记在本轮总结。出现在场景、时间线或召回标签里，单凭这一点不会进入人物列表或独立推演。
- 交付关键物件、约定、债务、重要知情、持续的协助或阻碍，需要以后认出同一个人时，当轮建档。没有姓名可先用可辨认的称呼，例如「北门守卫」。
- 只记录眼下有依据的词条。守卫代管银钥匙时记物件、保管人和归还约定；身份揭晓后沿用原档，补姓名和别名。离开当地、约定到期或暂时没出场都不自动删档。
- 人物共用同一结构，无须预先标注主次。近远景控制已跟踪对象的复查频率。人物页只显示已有内容的词条。

人物和主角共用身份、职务、阵营、身体状况、当前情绪及能力与专长词条。有已确认记录时按组显示。一个物件可分别关联所有人、保管人和使用人，每人档案中同一物件只列一次并注明各方角色。关系身份独立于双向态度；甲是乙的徒弟时，两人查看同一条关系，从各自方向阅读。背景更新按本轮原文提交，借用、免职或情绪变化只改动有依据的词条。

主角与人物档案共用已确认的世界属性、反向关联、随身物品和资产视图。外貌、体型、衣着、性格有正文依据时分别展示。物件的 owner 指向持有人；房产可直接使用地点档案，船车等重资产以「持有类别＝资产」区分。旧弧光数据仅为存档兼容保留，人物成长的经过可查剧情时间线。后台验证命令为 `node --import tsx --test modules/story-state/records.test.js modules/story-summary/tests/summary-result.test.js`。

「主角」和「人物」详情分别展示本人持有的计划与目标。计划是当下要完成的具体项目，目标是长期追求的方向。共同条目共用一个编号，各持有人看到同一状态、具体内容、条件约束和来源。计划完成后，目标仍按自己的剧情依据更新。旧计划有明确署名时按人物展示，其余可在人物页的「待归属的旧计划」查看。后台验证命令为 `node --import tsx --test modules/story-state/personal-agendas.test.js modules/world-records/update.test.js modules/world-records/proposal-review.test.js`。

「主角 → 当前牵涉」列出与主角同区域或直接牵涉主角的人物、事态和风物，并显示理由。地图有「区域」层级时，使用主角所在地向上遇到的第一个区域，包含它的所有下级地点。缺少区域层级时取最近的城区或城市；只有未分级的地点时，按本地层级或同名唯一地点判断。换区随位置重算，仍有直接牵涉的对象继续保留。后台使用同一份名单。开启相应演化后，近景每轮检查，有依据才推进一小步。其他对象处于远景，收到直接消息、重返当地或明显跳时等有据可查的变化才粗略复查。仅在本轮沉默会继续保留牵涉，明确脱离才退出。正文已经发生的事实照常生成提案，沿用原有确认与写入规则。

两档推演的后台回归命令为 `node --import tsx --test modules/story-state/involvement.test.js modules/story-state/ambient.test.js modules/xiaobai-os/apps/world/evolution.test.js modules/story-summary/tests/memory-storage.test.js`。

到访优先识别世界地点编号、名称与登记别名；含糊的同名地点不会触发新偶遇。后台自动推进人物动向或事态时，WorldEdit 必须核对旧状态并逐字引用本次已接受的 AI 正文，填写推进原因。保存的条目可展开最近一次推进依据；单纯请求结案的正文证据不会自动结案。后台回归命令为 `node --import tsx --test modules/story-state/ambient.test.js modules/xiaobai-os/apps/world/evolution.test.js modules/world-records/proposal-batch.test.js`。

局势页可按「全部／事态／风物」筛选。随正文独立更新的同一次模型调用整理风物与街头见闻，按当前分支、到访、来源楼层保存；新到访或显著跳时才有机会生成见闻。偶尔与活跃的抽取率分别为 18% 与 42%，关闭为 0。风物推演默认关闭，偶遇默认偶尔。平静的当前地点最多注入两条，见闻不自动转成购买、任务或正文事实。运行 `node --import tsx --test modules/story-state/ambient.test.js` 验证触发、退场及回退。

局势记录可填写概况、涉及方、影响范围、当前影响和解除条件。展开「局势历史」可查看当前分支有据可查的版本变化及来源楼层。幕后条目可以通过 situationId 关联同一聊天中的局势，单独展示。后台验证命令为 `node --import tsx --test modules/story-state/situation-history.test.js modules/xiaobai-os/apps/world/evolution.test.js`。

人物和局势页各自提供幕后推演开关与记录。两者使用已有的后台模型和触发时机。旧自动新闻设置沿用为局势开关；人物推演默认关闭。正文事实继续由独立更新记录。运行 `node --import tsx --test modules/xiaobai-os/apps/world/evolution.test.js core/kitchen-workspace.test.js` 可验证路由及两类推演的写入边界。

当前首栏为「主角」。页面按当前玩家的人物名、明确别名或地图玩家绑定识别身份，展示已确认属性、直接指向主角的关系，以及主角的在场与认知记录。同名无法区分时不合并档案。

## 当前界面（0.2.10 起，0.2.22 增补）

剧情时间线按来源楼层显示本轮总结，人物取自该轮的召回标签。剧情校对可以引用原文修订指定版本的总结，同时修正人物、地点、时间和关键词。修订随校对事务保存。受影响的阶段或章节在重新校对前退回到有效的下层总结。

已有聊天读取时会把旧事件卡的独有描述、前因和标签并入总结。只有导入边界的旧档显示为「旧档汇总」。旧卡迁移和剧情校对都不会执行世界命令。回退校对所在的批次，会恢复此前版本的总结和标签。

“剧情 → 剧情设置 → 总结提示词”分别开放本轮总结、篇目总结、章节总结的提示词，支持保存和恢复默认。独立更新生成本轮总结。校对者可依据正文引用请求生成阶段，多个阶段的共同主线收束后可请求生成章节；默认每五轮校对，未闭合时继续积累，历史摘要保留来源；后续正文按可见边界优先使用覆盖完整的高层总结。

剧情设置中的「保留最近原文（轮）」默认 5。一轮以一条已完成的正文回复为界，包括此前的用户输入。第 6 轮完成后，第 1 轮已有总结即可隐藏，后续正文读取其摘要。单独打开「按需注入相关早期原文」可找回相关片段。旧设置中的默认 6 楼迁为 5 轮，其他自定义楼数按两楼一轮向上取整。

新配置默认开启自动校对，每 5 轮触发一次。剧情校对页可独立设置 1–100 轮或关闭自动校对。旧配置保留已保存的启停及频率。一次补记跨过多个周期时合并为一次校对，覆盖待处理范围。

0.2.22 移除剧情板块的模块开关、当前聊天的“启用剧情总结”和“启用向量检索”。两项默认启用；旧关闭标记保留在原始数据中，但不再影响使用。向量参数始终可见，未配置向量模型时用关键词检索，配置后自动补齐向量，重排仍可选。

“总结范围”中的延迟楼数与单次上限不再作为用户设置：总是从已确认进度补记到最新已完成回复，内部每批最多 100 楼，积压连续分批。每批分别确认保存、核对来源与世界版本；失败、取消或收尾异常停止后续批次，已确认进度保留。最近原文显隐与注入设置独立保留；后厨总开关及自动总结暂停也保留。

0.2.21 显示“已自动写入”及版本，待处理的关联组从任一成员打开同一组表单，修改或拒绝也一起处理。同轮剩余多项可用“核对本轮全部变化”一次保存，保存失败保留整组输入。沿用原生 fieldset、按钮、折叠项和现有主题，不增加模态窗口或导航。

0.2.20 在世界变化提案中加入确认、修改和拒绝；过期项先打开核对表单。复用现有原生按钮、折叠项及右侧表单，不新增模态窗口。显示原提案与最终确认内容、处理说明和世界版本；保存期间禁用重复操作，失败保留输入并可重试。

0.2.19 的剧情检索设置只展示原文向量进度，移除锚点提取入口及前置提示，重排标为可选；未配置向量模型时提示可使用关键词检索。旧场景与事件数据仍在存档中，历史模型配置保留但不参与当前流水线。

0.2.18 在现有世界管理中增加折叠的“世界变化提案”，展示尚未执行的变化、旧值、新值、性质与原文依据；过期提案明确要求重新核对，可定位现有对象，不提供自动批准。沿用原生 details、文字、按钮及主题，不增加导航。0.2.16 已删除旧变量入口。

统一更新保存的区间摘要直接用于楼尾预览和展开阅读，即使事件列表为空也显示为“已写入”；来源范围仍按实际批次展示，不把区间伪装成独立单楼。历史旧区间继续显示原有事件摘要。

当前一级导航为 **主角／世界／剧情／规划／API 设置**，首次进入主角页（overview 路由）。世界默认打开人物，旧 world-records 链接仍进入局势。世界二级导航依次显示 **人物／地图／局势／设定**；剧情二级导航为 **剧情时间线／悬念簿／剧情校对／剧情设置**；设置改为 **API 设置**，只管理 API 连接与模型。此前版本的四标签／默认世界描述属于历史记录。

总览在原生抽屉内直接挂载，展示当前场景、故事时钟、在场与附近人物、计划、悬念、局面、近期剧情和世界状态。人物档案内增加认知和在场度，局势页追加结构化局面。楼尾采用可编辑的摘要与分组变化清单，默认由主回复附带总结，支持审查后写入。按钮、文本和折叠动效跟随宿主主题与时长。数据与上下文边界见 [STORY-OVERVIEW.md](STORY-OVERVIEW.md)，总结操作与保存边界见 [MAIN-REPLY-SUMMARY.md](MAIN-REPLY-SUMMARY.md)。

本工作台延续 SillyTavern 的原生视觉体系。参照柏宝书的顶部工具栏入口与楼尾交互结构，使用宿主门形图标标识后厨，不另建全局配色或字体体系。实现以 `core/kitchen-workspace.js`、`core/kitchen-embedded.css`、`style.css` 与各模块挂载代码为准。下文保留迭代记录：四标签、默认世界、展开工作区和横向滑入等旧描述不代表当前界面；导航以本节为准，面板沿用 0.1.7 之后的原生抽屉规范。

### 0.2.16 移除变量界面

“世界 → 更多”已移除变量页，原变量功能开关、楼尾按钮、编辑与恢复面板及样式均删除。当前状态在世界管理和对应实体／地图视图中展示。下面的 0.2.15 变量说明仅为历史记录，该界面不再存在。

### 0.2.15 变量保存恢复（历史）

本地变量从当前世界分支读取，编辑先确认保存再刷新显示。保存失败时保留表单输入，在本地变量区域显示错误和原生“重试保存／重新读取”按钮；重试复用原命令，重新读取放弃候选并关闭旧编辑框。读取和保存状态使用可换行的文字及 `aria-live` 状态区，不增加导航、主题或弹窗。全局变量保留原范围。组件交互已使用宿主 jQuery、真实面板及 DOM 夹具验证；本地浏览器被 Work 设置禁用，未新增桌面或窄屏截图，不能据此宣称完成布局或真实宿主验证。

### 0.2.10 界面精简

0.2.10 只调整信息层级，不改变数据、协议、存储键或模块边界。规则如下：

- 主任务留在首屏：总览首屏是当前场景卡、在场人物和未结计划／悬念／局面；重复的“查看人物／查看地图／查看局势／查看设定／查看剧情／查看世界／查看规划”跳转移除，改由一级和二级导航承担。
- 每个区域只保留一个主要动作：世界总览的“管理世界”同时显示待确认数量；世界管理保留“新增对象”和搜索，同步来源、登记交易、重新加载进入“更多操作”；楼尾展开后以“确认写入”为主操作，其他进入“更多”；地图设置有地图时只显示自动更新、投影和“更新地图”，重新绘制、重新加载和模型配置进入“模型与高级操作”；功能开关页的说明文字收进“说明”。
- 内容本身承担导航：总览和世界总览不再为每个分区重复放跳转按钮；待处理数量、状态和空状态仍以文字说明。
- 剧情总结设置移除只说明跟随酒馆的“外观”页；配色、字体、透明度和动效仍由宿主决定，不再占用一个设置分类。
- 收起不等于删除：所有路由、按钮、数据写入和确认步骤仍在，仅改变入口位置；世界二级路由仍由 `KITCHEN_ROUTES` 维护，楼尾动作仍走原有确认与撤销路径。

0.2.10 离线截图位于 `output/ui-simplification-preview/`：`overview-desktop.png`、`world-desktop.png`、`world-more-desktop.png`、`management-desktop.png`、`floor-desktop.png`、`floor-more-desktop.png`、`map-settings-desktop.png`、`map-settings-empty-desktop.png`。其中总览、世界和世界管理截图已在 0.2.12 重新生成，当前内容以 0.2.12 小节为准。夹具加载实际工作台、总览、世界总览、世界管理和楼尾组件；宿主主题、世界数据和提交接口由夹具模拟。地图设置为独立 Vite 组件预览，使用实际 `MapSettings.vue` 和 `map.css`，模型表单以占位块替代。截图不代表真实酒馆宿主或模型联调。

## 共享面板与导航

一个非模态面板承载五个一级标签，顺序固定为总览、世界、剧情、规划、设置。面板作为后厨 drawer 的 drawer-content fillRight 在右侧从顶端向下展开，无遮罩或焦点锁定；功能内容在面板内部滚动。二级入口以 `KITCHEN_ROUTES` 为准：

| 一级标签 | 主入口（路由） | “更多”中的入口（路由） |
| --- | --- | --- |
| 世界 | 人物（`people`）、地图（`map`）、局势（`situation`） | 设定（`lore`） |
| 剧情 | 剧情时间线（`memory`）、悬念簿（`suspense`）、剧情校对（`proofreading`）、剧情设置（`memory-settings`） | — |
| 规划 | 剧情规划（`planner`） | — |
| API 设置 | API 设置（`settings`） | — |

“更多”是原生 `details` 菜单：点击外部或按 Escape 关闭；当前路由位于其中时，摘要显示“更多 · 设定”等实际页面名，并保持选中样式。路由集合与挂载点仍由 `KITCHEN_ROUTES` 决定，收起只改变入口层级，不移除页面或数据。

- 剧情时间线集中展示章节总结、篇目总结和本轮总结。展开章节可读所属篇目，再展开篇目可读对应轮次。尚未归入上一级的总结独立显示。搜索会展开命中轮次的上级，分页以最外层条目为单位。三层提示词在“剧情设置 → 总结提示词”中编辑。
- 剧情设置归入“剧情 → 剧情设置”，集中总结规则、总结模型、向量召回、提示词、导入导出、服务器备份与清理回退；原记忆页设置按钮（`archive-manage-open`）在嵌入模式隐藏，数据管理入口复用设置视图，剧情校对从独立的二级导航进入。剧情规划保留在独立的“规划”一级标签。
- “API 设置”只管理命名连接、模型与连接测试，不再显示跨功能的“模块调用配置”总表。总结模型在剧情设置选择，规划模型在剧情规划选择，世界／地图模型在对应板块选择，校对模型在剧情校对页选择；配置的创建、命名和编辑仍在 API 设置完成。
- 在酒馆的“后厨 → 面板设置”勾选要显示的面板。关闭当前面板时自动打开可用面板，全部关闭后仍可从后厨的面板设置重新开启。
- 后厨门形按钮切换展开/收起，并维护 `aria-expanded`。首次默认进入总览页，后续展开恢复当前路由；点击一级标签进入该组首项。展开时把焦点交给所属一级标签；收起恢复到打开前仍存在的焦点元素，否则返回后厨门形按钮。
- 一级导航使用 `tablist`、`tab`，共享内容区为 `tabpanel`，并关联当前一级标签；当前标签是唯一 `tabindex="0"`。左右方向键循环切换并激活，Home/End 转到首尾。二级入口使用普通按钮及 `aria-pressed`，同组切换不重建按钮，以保留焦点。
- 面板收到未被处理的 Escape 时收起；共享 OS iframe 内的 Escape 先消费详情或弹层返回，根页面再通知宿主收起。记忆、规划 iframe 的局部快捷键仍由各模块处理。切换聊天重置并收起工作台。离开变量路由或收起面板停止其观察器。
- `openKitchenTab()` 按当前路由自动选中所属一级标签；原变量、地图等入口保留。注意 `world` 指世界总览，`situation` 指局势；旧 `world-records` 转到总览，OS 世界入口改用 `world-engine` 并映射到原 OS `world` 应用。扩展设置中的“打开酒馆后厨”和消息操作区“剧情总结”入口继续保留。

## 世界与总览

世界栏目表示整个横向世界状态；人物、局势、设定、变量和地图是分类视图，后台演化是运行机制。总览汇总同一状态的对象、事实、待处理数量及近期变化，无独立存储或 AI 调用。人工管理操作随世界管理页面暂时下线。代码仍以 world-records 命名内核，保留既有数据库以兼容存档；分类页的权威数据接管尚在进行。

总览与世界管理使用独立原生 DOM 挂载点，共用同一个服务和存储。旧剧情 iframe 内部的 world 视图仍表示局势，宿主桥将其映射到外层 situation，防止内部切换误开总览。

## 模块边界与状态

- 记忆、规划与共享 OS 内容保持同源 iframe 边界，以隔离文档样式和全局变量；这不是安全沙箱。主题桥在加载后注入嵌入样式，复制宿主颜色与阴影变量、字体、字号和动效时长，并观察宿主根节点、body 的 class/style/data-theme 变化；卸载时断开观察器。
- 剧情时间线、局势与设定、人物、关系及剧情设置共用稳定的记忆挂载点和 iframe；通过 `KITCHEN_MEMORY_VIEW` 与 `archiveView.switchView()` 切换内容，不搬移或重载 iframe。内页发起的视图跳转同步外层路由。
- 人物与关系复用现有数据，但分区显示：人物与关系页在同一视图展示人物名单、档案与关系图；默认侧栏上下排列，展开到 800px 以上时并排。旧 relations 路由转向 people。剧情 iframe 内原有的剧情/人物/世界标签在嵌入模式隐藏，由外层导航统一承载。
- 人物名单位于 `archive-people` 根部，不随关系图隐藏；人物搜索过滤名单。嵌入模式的 `showPerson()` 转到外层人物路由并保留所选人物，关系页名单和关系节点均可据此打开对应档案；手机端直接显示档案，不把档案移入弹窗。
- 地图、后台演化、API 设置共用一个 OS 挂载点；切换路由不把已加载的 OS iframe 在父节点间搬移，避免重载和状态丢失。变量面板直接嵌入共享容器。
- 嵌入模式隐藏重复标题、主题快捷按钮、关闭按钮及设备外框；0.2.10 起不再保留只说明外观的设置分类，保留必要的内部操作与“返回上一层”。原模块状态、存储键、宿主桥接与业务流程继续归原模块管理。
- 加载期间挂载点设置 `aria-busy`。停用功能、初始化失败、缺少聊天等情况使用面板内状态消息，提供“重试”和“前往 API 设置”；功能开关保存后刷新生效。空数据由模块表达，例如记忆页提示“还没有剧情记录”，不能展示虚构内容。

## 窄屏

桌面默认侧栏宽度为 380–520px，参考宿主聊天区外侧空间；展开后上限 1040px。面板从顶部工具栏下延伸至窗口底部。600px 以下全宽从右侧滑入、去掉侧边框，标题和内容缩减内边距；五个一级标签分配可用宽度，二级导航以主入口加“更多”收束并允许换行。人物页在手机端直接显示人物档案，无需先经过关系图。0.2.10 的窄屏截图覆盖世界主入口、“更多”菜单和楼尾摘要；不能把页面无横向溢出等同于所有二级入口同时可见。

## AI 回复下的摘要

- `modules/story-summary/floor-summary.js` 在叙事 AI 回复正文后挂载 `inline/panel.js` 的楼尾卡片，默认收起。两行卡头显示从 1 开始的楼号、故事时间、写入状态和摘要预览；收起状态不再显示番外和提取图标，无摘要时右侧显示“总结本楼”，已有摘要时显示“重新总结”。用户消息、带原生类型标记的系统消息不挂载；被旧隐藏机制标记为 `is_system` 的普通 AI 回复仍可挂载。
- 卡片颜色、字体和焦点轮廓读取宿主变量，折叠使用宿主动效时长并遵守减少动态效果偏好。时间与地点用可换行标签，摘要保留换行；变化按人物、认知、物品、变量、计划、悬念、局面、剧情、世界等纵向分组。条目用操作标记、标题和说明区分内容，不依赖颜色独自传达状态。
- 点击时间、地点、摘要或条目就地编辑；文本框随内容增高，保留保存、取消及逐条删除入口。保存中禁用重复操作，失败保留当前输入并显示原因。整楼删除需确认，保存后重算后续派生结果；原始聊天正文保留。
- 默认自动写入完整、有效的主回复总结。启用“审查后写入”时显示待审查，条目保存先存草稿，点击“确认写入”才更新剧情资料。展开后的页脚以“确认写入”为主操作，番外、重新提取、查看剧情和删除摘要收进“更多”。待总结、输出未完成、格式有误、已写入、番外和已删除各有明确状态；只有点击“总结本楼／重新总结”才调用副 API，显示、补齐或提取面板内容本身不另调 AI。
- 提取只读取本楼的协议；已有记录、草稿或正在编辑时显示覆盖确认，取消确认保留未保存输入。标为番外会撤去该楼派生记忆并排除召回，取消后重放恢复；原始正文不因此隐藏。
- 旧区间总结明确标“旧版区间总结 · 第 A–B 楼”，保留真实批次范围并提供“在剧情资料中编辑”，不把跨楼记录拆成猜测的单楼变化。“查看剧情”位于“更多”中，仍携带当前楼层打开剧情时间线。
- 聊天切换、消息编辑／重抽／删除、更多消息加载及摘要状态变化触发更新；停用或卸载时清理卡片。编辑绑定聊天和回复版本，来源变化时阻止旧输入覆盖新资料。

0.2.6 离线证据位于 `output/main-reply-preview/`：`collapsed-desktop.png`、`expanded-desktop.png` 与 `expanded-mobile.png` 展示卡头及纵向分组；`light-desktop.png`、`light-mobile.png` 检查浅色主题；`edit-mobile.png`、`long-location-mobile.png`、`extract-confirm-mobile.png`、`omitted-mobile.png` 与 `error-mobile.png` 覆盖编辑、长字段、提取确认、番外及保存失败。`checks.json` 的 9 项断言通过且 `errors=[]`，包含取消提取保留草稿和失败保留输入。夹具加载实际楼尾组件，提交接口由夹具替代；这些证据不代表真实 TauriTavern、真实模型或完整数据链路验证。

## 0.1.4 面板开放与样式统一

所有面板均可在未选择对话时打开。地图、后台演化提供无数据状态，并禁用依赖当前故事的生成、更新和属性写入。模型接口可读取、保存共享预设，判定规则可提前配置。未绑定聊天的激活仅在仍未选择聊天时有效；选择或切换聊天会使旧页面请求失效，不借用上一段聊天的数据。

模型接口、地图、后台演化和骰子通过嵌入样式映射到同一套宿主变量，字体、间距、边框、圆角和焦点样式统一；浅色或深色宿主变更即时同步。底部返回入口使用单行布局并继承正文颜色。模型表单使用中文字段名，移除旧短信样式请求与随机世界配图。

当前离线截图位于 `output/panels-preview/`：桌面模型接口、地图空状态／有数据状态、后台世界空状态／有数据状态、行动判定，以及窄屏深浅色模型接口、浅色地图和地图设置。夹具加载实际生命周期、控制器、共享配置仓库及构建后的 Vue 页面，服务器文件接口、地图／世界数据源和宿主由夹具模拟。验证未进入聊天时接口保存与规则设置、地图／世界操作禁用、进入聊天后的地图显示及主题实时切换。图中地区为测试样例；没有连接真实 Tavern、真实存档或付费模型。

## 0.1.5 原生抽屉行为

- 内容直接挂在 `#tk-topbar` 内，使用宿主 `drawer-content`、`openDrawer`、`closedDrawer`，优先调用公开的 `doNavbarIconClick`。不包含该导出的 Tavern 宿主采用兼容类切换，仍由其原生样式负责展示。
- 宿主点击外部、打开其他非固定抽屉时可以直接关闭后厨；观察 class 变化同步 aria-expanded、inert 和路由可见性。固定的 pinnedOpen 抽屉不被后厨关闭。
- 默认宽度跟随 sheldWidth；桌面“展开工作区”使用更大宽高，再次点击恢复。移动端保留底部输入区；减少动态效果的系统偏好会关闭后厨动画。
- 共享 OS 根页面没有底部导航，也没有无效返回按钮。有详情层时显示内容顶部返回；模态弹层继续使用自身关闭按钮和 Escape，避免重复导航。原世界文章页的重复返回按钮在嵌入模式隐藏。
- 点击收起、宿主自动关闭或在共享 OS 根页按 Escape 均保留已挂载的页面及其输入；切换到其他工具仍遵循原工具生命周期，不能保证跨工具切换保留未保存表单。聊天切换继续重置工作台并校验旧会话。

0.1.5 离线截图保存在 `output/native-drawer-preview/`：`api-desktop.png` 展示默认原生抽屉，`expanded-desktop.png` 展示展开工作区，`world-detail-back.png` 展示顶部详情返回，`api-mobile-light.png` 与 `map-settings-mobile-light.png` 展示窄屏和浅色主题。宿主抽屉逻辑来自本地官方快照，其余宿主状态由夹具模拟；真实 TauriTavern 联调仍待验证。

## 0.1.8 入口与动效

- `plugin-entry.js` 同步启动轻量 `kitchen-bootstrap`，挂载入口后再动态导入 `kitchen-runtime`。设置文件、模型模块和功能初始化不再阻塞按钮；运行时到达前允许打开带加载状态的面板，初始化失败保留入口和重新加载提示。扩展仍遵循宿主的加载顺序，不能保证早于宿主调度出现。
- 持续观察工具栏的创建和替换，位置正确时不搬动已有入口或 iframe；原生按钮晚到时仍保持用户管理／后厨／角色管理顺序。
- 控件进入与退出使用同一宿主动效时长及 ease-in-out；共享 OS 路由使用对称透明度过渡。同步显示隐藏的剧情、规划、下拉项及变量表单不再单向播放进入动画。宿主减少动画偏好同时作用于面板与嵌入页。
- 宿主主题改变时同步关系图配色；地图、模型接口、后台演化与骰子继续通过主题桥跟随。离线验证结果见 VALIDATION.md。

## 0.2.0 世界档案

世界下新增“档案”。管理界面直接挂载在原生面板中，不新增 iframe、窗口或独立主题。名称搜索、类型过滤、对象详情、来源候选、变更历史和存档管理共用一页；新增、编辑与交易在详情区域使用内联表单。所有来源内容以纯文本或受控 DOM 呈现。

保存期间禁用重复操作；失败保留表单。切换聊天清空旧视图并使未提交任务失效。未进入对话时可以打开入口，内容提示先选择对话。来源同步不覆盖正在编辑的表单，保存遇到版本变化时要求重新加载。

## 0.2.2 首帧与内页切换

剧情、规划与 OS 页面在 HTML 阶段加载嵌入样式，宿主主题桥完成首轮同步后才显示 iframe。嵌入 OS 不渲染手机状态栏或桌面，挂载点缺失时返回未就绪，不能回退到独立模态窗口。

内页路由直接替换内容，取消手机壳先退场后入场的串行动画；地图详情、规划与剧情标签也不单独播放入场动画。外层继续使用酒馆抽屉的向下开合，控件反馈沿用宿主时长，加载和保存指示仍保留。

## 0.2.3 移除手机外壳

共享工具容器只支持后厨内嵌。独立弹窗、桌面／壁纸、快捷启动器、状态栏、底部导航、排序设置与对应资源均已删除；不再通过 embedded 条件或 CSS 隐藏这些组件。原 Device 改为 KitchenToolView，仅负责业务页面容器、加载、失败重试与内部返回。

init 不创建 UI；open 需要已连接挂载点和有效页面 ID。关闭工作台仍保留输入，聊天切换与清理仍释放会话。地图等工具自身的编辑弹层继续保留。

可在项目根目录运行 `node --import tsx --test core/kitchen-workspace.test.js modules/story-summary/tests/raw-memory-ui.test.js modules/world-records/update-llm.test.js`，在后台验证工作台导航、三层提示词入口与总结请求。
