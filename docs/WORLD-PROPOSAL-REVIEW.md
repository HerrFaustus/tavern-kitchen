# 世界变化提案的确认与提交（0.2.21）

## 使用流程

每轮独立整理继续生成摘要、标签和世界变化提案。摘要与提案确认保存后，宿主先核对正文和版本，再自动提交本轮明确且无冲突的关联组。剩余项目保留在世界管理的“世界变化提案”中：

- **确认写入**：按原提案提交。
- **修改**：核对当前值，修改新值、性质或记录内容，再确认保存。
- **拒绝**：保存拒绝结果与可选说明，保留原提案。
- **核对并确认**：世界已经变化时，先展示原提案与当前值，人工重新核对后提交。
- **核对并一起确认**：关联组使用同一表单核对、修改和保存；从其中一项点击“修改”或“拒绝”，也会处理整个待处理组。
- **核对本轮全部变化**：同轮剩余多项可以一起核对并保存，包含没有分组信息的旧提案。

字段提案锁定原对象和字段；剧情状态锁定记录 ID 与类型。原文依据不能改换。新增对象可以修改名称、分类和别名。原提案始终保留，已处理项显示最终内容、性质、处理说明和世界版本。

## 自动确认条件

原总结请求中的每条新提案增加 `groupId`（关联组）和 `certainty`（`explicit`、`inferred` 或 `uncertain`），不增加第二次模型判断。缺少这些信息的历史提案继续人工处理。

自动写入必须同时满足：

- 整组来自同一已完成、身份明确的正文轮次，逐字依据来自 AI 正文；完整增量来源、候选、确认记忆和当前分支仍匹配。
- 整组均为明确变化，引用所在句未含已识别的条件、否定、推测或未来意图；属于事实，或明确的人物认知、计划。认知和计划保留性质，传闻、推测、创作候选和未分类内容不自动升格。
- 原始世界内容、每项旧值与当前状态一致；本轮没有已报告冲突，没有重复目标或既有执行效果。
- 关联组没有已经单独处理的成员；同一增量来源的同一目标没有被人工拒绝。组合后的引用、数值、身份、名称和归属关系也通过内核检查。

买卖中的扣款、收款与归属须同组。脚本还会把同轮共享交易参与者的金币与归属变化合并，防止模型误拆关联组。组内有一项不确定，整组留给人工；其他独立且明确的组仍可自动写入。自动选择出的同轮变化共用一笔世界事务，不逐条落账。多轮积压中若有多个轮次可自动提交，整批保留人工核对，避免跨轮套用同一旧基线。

明确程度由已有总结模型依据正文给出，脚本检查来源与约束并保守拦截常见含糊表达；这不是独立的事实真伪裁判。异常的组合效果保留待处理，不降级为逐条自动写入。自动结果显示“已自动写入”和对应世界版本。

## 写入内容

| 提案 | 确认后的结果 |
| --- | --- |
| 已确认事实字段 | 写入世界实体字段；位置与归属引用稳定对象 ID，金币等数值继续校验 |
| 传闻、认知、意图等非事实字段 | 保存为原性质的待确认记录，保留当前事实值 |
| 新增对象 | 创建稳定身份；非事实对象另外保留待确认的存在记录，不自动获得事实字段 |
| 已发生的场景、时钟、在场度和其他剧情事实 | 写入世界的 `story` 状态，覆盖同 ID 的旧剧情投影 |
| 人物认知与计划 | 保留获知者、相信／误解等性质，以及计划的状态、期限和结案原因 |
| 创作候选或尚未分类的场景变化 | 保存候选；不替换实际场景、不推进时间 |
| 已确认的剧情记录撤回 | 保存撤回标记，覆盖旧投影；原摘要 JSON 保留 |

新世界剧情状态进入总览、人物阅读、后续正文上下文和下一次全视更新输入。旧剧情 JSON 是来源记录，不因批准提案而被另写一遍。世界已接管的剧情记录不会再通过旧记忆注入相反的当前值。完整双轴注入和知情视图仍按后续路线开发。

## 来源、版本与防重

人工与自动确认使用既有世界命令与 IndexedDB 事务。同轮关联的实际字段／对象／剧情变化、各项处理结果、同一世界事件及回执一起保存，事务失败时一起回退；批内剧情投影先合并再保存，不会互相覆盖。

提交固定世界、分支、世界版本、世界内容指纹及当前剧情状态指纹。提交前重新核对完整增量原文、候选身份、确认记忆和目标旧值。切换聊天、切换后返回原分支、修改其他字段或修改剧情状态，都不能让旧表单覆盖新状态。来源身份不明确时不能执行效果。

处理身份使用原请求与提案序号。同一结果重试直接读取既有回执；已经处理的提案不能换一套内容再次提交。同轮回执同时保存整笔提交与逐目标的来源／效果编号，不能通过拆批、换请求、换传输命令或人工／自动竞争再次执行同一目标。本轮已经由其他命令执行的字段变化也不能再次扣款或移动。重复完成通知和重启恢复沿用已经保存的处理记录，不另设易丢失的“已自动提交”开关。

拒绝记录没有执行效果来源，不会因后来改文被误认为已扣款。已确认来源被改写时，世界保留原结果与回执并要求核对，不自动撤销后续人工状态；原有历史分支恢复路径继续有效。

每次处理的历史只保存各项决定，避免把整批原文和其他提案复制进每条处理事件。分支、导出和恢复会重放处理记录，并校验其与实际效果、自动／人工方式及回执一致。包含批量处理与逐目标来源回执的档案须使用 0.2.21 或更新版本恢复；0.2.20 的单项处理与更早档案继续可读。

## 当前边界

本版接通同轮原子提交、明确变化自动确认及人工兜底。摘要确认与世界提交分别使用宿主和世界存储，仍由既有交付恢复机制续接，不能称为跨库原子事务。完整知情筛选、阶段／章／篇摘要树及容量分区仍待后续实现。此流程本身不增加模型请求。
