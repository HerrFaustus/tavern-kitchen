# 主回复总结与楼尾清单（0.2.6）

默认由酒馆主 API 在本轮故事末尾附带结构化总结。回复结束后，后厨提取并写入既有剧情资料；无需为此配置后厨总结 API。未输出、未输出完整或格式错误时，楼尾显示状态，允许补写或重新提取，不自动改用独立 API。

## 设置与操作

在 **设置 → 剧情设置 → 总结规则** 选择“主回复顺带总结”。默认自动写入；打开“审查后写入”后，主回复中的总结先显示为待审查，编辑草稿不会改变当前世界／剧情资料，点击“确认写入”才提交。保留“独立总结（兼容旧流程）”作为主动选择的旧流程；主回复模式隐藏旧模型连接、自动触发与范围设置。

每个 AI 楼尾采用柏宝书的交互结构：

- 两行卡头：楼号、故事时间与状态，下方摘要预览；点击展开或收起。
- 右侧番外按钮不计入该楼的派生记忆，取消后重放恢复。原始聊天正文保留，不因标为番外而隐藏。
- 右侧提取按钮重新读取这份主回复，**不发起模型请求**。已有记录、已保存草稿或打开的编辑表单时，覆盖前需确认；取消确认保留未保存输入。成功的显式提取直接写入，即使已启用审查模式，也不另存为待审查草稿。
- 时间、地点与摘要点击就地编辑；人物、认知、计划、悬念、局面、剧情、世界事实等分组纵向排列，每条可编辑或删除。文本框随内容增高，保存失败保留输入与错误提示。
- 已写入的清单保存后重算后续派生结果。整楼摘要删除有二次确认，保留原始回复，可再次提取恢复。

楼号沿用后厨的从 1 开始编号，卡片默认收起。用户消息与带原生类型标记的系统消息不显示卡片；旧隐藏机制标记为 `is_system` 的普通 AI 回复仍可显示。配色、字体和动效跟随酒馆，不增加独立主题。旧版区间总结仍明确标注真实范围并进入剧情资料编辑，不把跨楼总结冒充单楼记录。

## 协议与来源

主生成拦截器只在叙事生成中注入协议，要求主 API 在正文末尾附带唯一的 `<kitchen_summary>…JSON…</kitchen_summary>` 块。静默工具请求不注入。JSON 包含必填 `summary`、可省略或使用空字符串的 `timeStart/timeEnd/date/location`，以及 `updates` 下的 `events/factUpdates/arcUpdates/newCharacters/keywords/characterAliasUpdates/storyUpdates`。

使用酒馆原生的显示／提示词正则隐藏协议块，原始消息仍保留 JSON，方便审查和重新提取。后厨文本过滤器也会去掉该块，防止成为第二份叙事证据。宿主关闭正则扩展时，原生隐藏规则无法工作；此时原始协议可能显示在聊天或后续宿主上下文中，后厨自身仍会过滤它。

事件来源楼号由程序绑定到本条 AI 回复和紧邻的玩家消息，忽略模型自报来源。未知更新字段、无效记录、超长数据和不成立的事件引用会拒绝写入。时间取自故事，架空历法只保存标签。主 API 仍需遵循协议；它的输出质量不能由解析器保证。

## 保存、编辑和召回

每楼的结构化总结、来源指纹、稳定事件 ID、番外／删除标记，存入原 `storySummary.summaryHistory` 的 `floorEntry`，不另建第二份世界状态。待审查的人工修改存入 `floorDrafts`，绑定当前回复版本。清空或导入总结时清理旧草稿。

编辑历史楼层采用“精确回退 → 修改本楼 → 重放后续楼层及修订”的同一笔确认保存。后来的修订只覆盖其实际修改的字段。后续仍引用被删除事件、修订依赖已移除对象，或无法重放的旧版整表替换，会中止并保留原数据。保存失败、聊天切换、正文或候选回复变化时不会把旧编辑写入新的来源。

尚未总结的旧楼层不会因为较新的单楼总结而被批量隐藏。番外楼不参与后厨的剧情派生、原文块新建、独立旧总结输入和最终记忆召回；既有原文／向量缓存可保留，但不能因此重新进入记忆注入。取消番外恢复其已保存的摘要与变化。

主回复模式停用旧的自动区间总结及后台 L0 模型摘要提取。若用户启用了向量召回，Embedding、重排等既有检索服务仍按其配置工作；维护助手、规划器和手动高级操作保持原来的显式入口。

## 实现边界与参考

楼尾清单消费后厨已有的剧情、人物与结构化世界观察协议。`factUpdates` 中的物品属性和 `变量.*` 是总结事实，不能代替变量管理器的真实指令执行、地图坐标修改或世界内核交易。本版没有把柏宝书的所有后端系统搬进后厨，也未实现完整 MVU 接管。

参考本地柏宝书 1.3.5 的 `FloorPanel.vue`、单楼编辑／番外及派生重放机制，按后厨现有数据结构独立实现。验证使用真实保存／回退回归测试及真实组件离线浏览器夹具；不等同于已在用户的 TauriTavern 上进行实聊或付费模型测试。
