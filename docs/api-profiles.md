# 模型接口与 API 配置档案

在「设置 → 模型接口」集中创建、命名和编辑配置，在「模块调用配置」或各模块自己的设置中选择。配置库的当前编辑项不代表正在使用的模型。保存修改会影响所有引用此配置的模块；重命名保持引用，正在使用的配置不能删除。

- 剧情总结、剧情规划、剧情助手分别绑定。
- 世界与地图后台共用一个调用配置：它们当前由同一次后台维护调用协同处理，避免重复调用。
- 召回语义整理、向量嵌入、召回重排分别绑定。向量和重排使用对应用途的 OpenAI 兼容接口；语义整理使用直连 OpenAI 兼容文本接口。
- 剧情总结保留「沿用酒馆」。规划及后台工具调用要求选择独立配置。
- 联网检索渠道和密钥仍是全局设置，保留在模型接口页面末尾。

## 从酒馆导入

「复制酒馆主接口」复制当前聊天补全渠道的地址、可读取密钥、模型和常用生成参数。「只复制酒馆连接」复制地址与鉴权，留空模型和采样参数；拉取模型后选择并保存。两种操作都会创建独立命名副本，不改变酒馆主接口，也不自动改变模块绑定。

支持 OpenAI、自定义、Claude、Google AI Studio、OpenRouter、DeepSeek、Groq、硅基流动、Mistral 和 xAI。其他渠道或文本补全接口会提示手动配置。若宿主不提供可复制的密钥，连接副本会提示补填；没有自动声称鉴权成功。自定义请求头／请求体扩展不复制，页面会提示检查。导入只取当时快照，不持续跟随酒馆。

## 数据与执行

沿用 CommonSettingStorage 的 textApiPresets 配置记录，以稳定 ID 引用命名配置；profilesVersion 标记统一库迁移。首次加载把原剧情／规划预设、原 Agent 预设和召回接口迁入，保留原名称含义、密钥、模型和各自绑定。旧 Agent 数据保留用于全局联网设置与回滚，不再决定后台模型。保存迁移失败可重试，不覆盖原数据。

调用开始时解析所选配置，运行中的调用保留其快照。库内编辑、命名、导入和绑定分开保存。用途不匹配的配置不能绑定；缺失配置会报错，不自动替换。修改向量模型后应重建既有向量，避免不同模型生成的向量混用。

加载有超时、错误信息和重试入口。页面不再依赖旧 Agent 表单的响应式对象克隆和预设编辑状态。

## 验证边界

自动测试覆盖迁移失败重试、稳定引用、编辑不改绑、用途校验、导入快照和运行时解析。离线浏览器使用真实构建页面与宿主消息链路，模拟保存和导入；不消耗用户模型额度。宿主允许读取密钥与供应商连通性仍由实际安装环境决定。
