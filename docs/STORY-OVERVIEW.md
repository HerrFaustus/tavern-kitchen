# 总览、场景与进展（0.2.6）

一级导航为总览、世界、剧情、规划、设置。首次打开进入总览；世界原“总览”改称“世界状态”，继续展示完整世界对象与已确认状态。旧 world/world-records 链接保留原落点。

总览展示当前场景与故事时钟、在场和附近人物、未结计划、悬念、局面、近期剧情、人物轨迹与近期确认的世界状态。已结事项折叠展示，并保留结案原因。详细人物、世界、剧情和规划均可从总览进入。界面固定跟随酒馆，不新增主题、独立窗口或动画。

## 数据与更新

`modules/story-state/records.js` 定义结构化观察，保存在已有 `storySummary.json.storyRecords`。0.2.6 默认从主回复附带的总结读取 `updates.storyUpdates`，自动写入或经楼尾审查后，在同一笔总结保存中维护以下记录；不为总览再发一次模型请求。主动选择独立总结兼容模式时，仍读取旧总结结果的 `storyUpdates`。

| 类型 | 内容 |
| --- | --- |
| scene | 唯一当前场景：地点、局面、完整在场名单、持续张力、明确待兑现的动作或约定 |
| clock | 唯一故事时钟：原文时间标签，可选明确公历日期 |
| person | 人物在场度：在场、附近、离场、未知，以及判断依据 |
| knowledge | 认知归属、内容、已知／相信或误解／怀疑、获知依据与故事时间 |
| plan / suspense / situation | 稳定 ID、标题、描述、未结／完成／取消／失败、结案原因和可选期限 |

每项更新替换完整记录；未提及的记录保持原值，空字符串清除字段，显式 remove 撤回记录。计划改期、结案和认知纠正复用 ID，不另建重复项。场景的完整名单优先于同批或更早的在场观察；离场不删除人物认知。人物名称复用已有别名规范，记录 ID 不随改名改变。

来源楼层由代码填入，不采信模型自报的来源元数据。主回复总结绑定本条 AI 回复及紧邻玩家消息；旧区间总结仍标注实际批次范围，跨楼变化不冒充单楼行为。旧存档没有这些字段时保持空状态，不根据旧事件猜测当前场景。

## 楼尾清单与回退

AI 回复下方展示可折叠、可编辑的摘要与分组变化清单，涵盖剧情、世界事实、人物、叙事线及场景进展。主回复楼尾读取本楼保存的结构化总结或待审查草稿，使用纯文本呈现；旧区间记录保留批次范围并进入剧情资料编辑。操作说明见 [主回复总结与楼尾清单](MAIN-REPLY-SUMMARY.md)。

已提交清单代表该楼的变化，不等同于当前世界状态。修改或删除历史楼层时，先精确回退，再重放后续总结及维护修订；有未解决的依赖冲突时保留原数据。审查草稿不更新总览，确认写入后才参与派生；标为番外撤去该楼影响，取消后恢复。人物页展示认知与在场度，局势页展示结构化局面；维护助手继续复用原 ID、类型、维护事务与撤销记录。

新记录参与总结批次撤销、源消息修改／重抽／删除后的回退及记忆包导入导出。源状态失效时总览暂不展示旧场景；聊天切换清空视图。导入新聊天时来源楼层重新绑定到导入边界，不携带旧聊天楼层。

## 时钟与上下文

时钟来自剧情，不使用系统当前时间推演故事。明确公历日期可计算今天、昨天、明天及天数差；架空历法仅保留标签，不猜测月份长度。期限过去不会自行结案、自动完成计划或推测行动结果。

场景与进展进入已有召回的世界约束区，共享原总预算，其中最多使用约 800 token；不增加单独检测或生成调用。相关在场人物与本轮焦点人物的认知可进入上下文，附近人物保留在场信息；其他认知保留存档。认知明确属于其持有人，不提升为客观世界事实。规划器沿用已处理的宿主请求，因此能够消费这份上下文；未采用剧情召回时不会另起一次查询。

## 当前边界

总览本身只投影已有已提交剧情状态与世界内核状态，不另存快照或调用模型。新结构化观察仍由剧情总结拥有，世界内核中人工确认的事实继续由原内核拥有；本版尚未将所有模块迁移到同一事件账本，也未实现后台自治或世界书接管。

这些记录在下一次成功总结后开始填充；旧楼层不会为补齐显示而自动额外调用模型。在场筛选只约束新增认知块，不能隔离宿主或其他插件已经提供的全知信息。

参考柏宝书的功能机制，独立实现，未复制其源代码。
