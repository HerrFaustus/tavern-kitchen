## 第一阶段的历史行为（0.2.7–0.2.12）

主回复唯一的 `<kitchen_summary>` JSON 根对象增加 `anchors: [{scene, where, edges: [{s, t, r}]}]`。每轮 0–2 张卡，每张最多三条已发生的互动，`scene` 为 15–4000 字符，`where` 最多 200 字符；互动三项各为非空且最多 200 字符。协议与编辑操作见[主回复总结与楼尾清单](MAIN-REPLY-SUMMARY.md)。

缺少 `anchors` 时只允许以合规长度的摘要降级为一张无边场景卡；显式空数组表示不生成锚点。新楼层带 `anchorVersion: 1`，锚点和摘要在同一确认提交中生效。生成回执标记为 `main_reply_anchors`，参与精确撤销与后续重放，隐藏于独立 Agent 运行列表。

内容参与锚点 ID，修订后清理失效向量与召回缓存；Embedding 补齐使用已有向量维护路径。主回复模式不再另调模型提取锚点，既有显式高级操作与独立总结兼容入口仍保留。

## 历史发布边界与兼容

0.2.7 没有统一 MVU、地图与世界内核的权威状态、实体引用或事务；现有世界档案内核与来源同步不能等同于第二阶段完成。锚点中的互动是叙事证据，不能代替物品交易、真实变量执行或地图修改。

旧 0.2.6 已提交楼层不自动添加 `anchorVersion` 或补写锚点；普通重放和摘要编辑保持原有边界。需要显式提交含 `anchors` 的修订才能接入。历史数据自动回填不属于本次交付。

现有分层记忆、人物认知展示、ENA 规划和世界后台是后续阶段的基础，不等同于已完成章篇压缩、动态上下文或多作家编剧室。本次验证限于自动回归与真实组件离线浏览器检查，未完成真实宿主和付费模型对话联调。

界面继续遵循[原生工作台约定](WORKSPACE-UI.md)，不新增独立设计体系。上游来源与修改说明见 [UPSTREAM.md](UPSTREAM.md)。

## 第二阶段进展

0.2.8 接通权威字段的叙事读取，0.2.14 接管地图，0.2.16 删除旧变量系统和 0.2.15 的兼容层。后续直接以世界字段、来源与事件构建统一独立更新，不再进行变量路径绑定。旧数据仅作历史 JSON 保留。见[当前契约](WORLD-ARCHIVE.md#0216-移除旧变量系统)。

0.2.17 将新独立摘要批次与每轮原文、候选和世界分支关联；确认保存后的交付可恢复，未确认记忆不推进连续覆盖位置。来源效果按脚本保持的效果编号防重；来源失效时阻断叙事读取，人工状态不自动撤销。旧摘要不补造来源，自动依赖修复与完整统一交付仍待开发。下一项是 P2 全视输入与统一整理。见[来源契约](WORLD-ARCHIVE.md#0217-每轮来源与执行回执)。
