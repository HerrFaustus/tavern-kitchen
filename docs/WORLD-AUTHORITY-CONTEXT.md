# 统一世界状态：权威读取（0.2.8）

本版落实架构路线第二阶段的第一部分：世界档案中已经确认的字段进入实际续写上下文，剧情与地图通过已有来源绑定复用同一实体 ID。完整的变量、地图写入迁移仍未完成。

## 数据权威与提交

世界档案继续由 `world-records/domain.js` 的命令、版本检查与单笔 IndexedDB 事务维护。稳定实体 ID、来源绑定、字段来源、事件和收据保留。候选、传闻、角色认知、计划或创作提案，不因出现在来源中而自动成为事实；只有写入已确认字段的数据进入本版权威上下文。

服务在事务确认后才发布当前分支的只读投影。失败提交保留此前状态；历史分支选择、恢复与成功交易发布对应分支结果。来源同步仍只产生身份与候选，不覆盖人工确认字段。

## 实际生成链路

叙事生成前先同步已经加载的来源、读取当前聊天绑定的世界分支，再运行剧情召回。未建立世界的聊天不会仅因生成而创建世界或回填历史。读取失败时清空本次世界槽并停止本次发送，避免继续使用未知时效的状态；可重试。

独立世界槽使用宿主 `IN_CHAT`、系统角色、深度 1。只有叙事生成注入；静默工具请求清空槽位。聊天／账户切换、模块释放或世界状态变化会使旧投影失效。世界变化同时使剧情召回的预取／复用缓存失效，下一次读取采用新状态。

上下文只包含已确认字段和实体引用的名称、ID，不包含待处理候选。按最近三条消息涉及的名称／别名优先，再按稳定顺序选取，最多 4000 字符；完整字段放不下时跳过，不截断数值、引用或 JSON。此规则只是本版预算选择，尚非空间或角色认知过滤。

## 剧情与地图

剧情事实依据已保存的 `memory` 来源记录、别名及来源键绑定到世界实体。已被世界确认的同字段不再作为旧当前约束注入；未绑定、同名歧义及其他字段仍走原有召回。即使某个世界字段因预算未展开，也不会让旧冲突值重新变成当前事实。剧情原文、历史事件、总结存档和维护记录不被改写，过去发生过的事仍可作为历史证据召回。

地图上下文依据 `map/place:*`、`map/actor:*` 绑定投影当前名称、地点描述、父级地点和人物位置。目标地点没有唯一可用地图绑定时，省略旧位置，不猜测映射；完整世界槽仍可提供目标实体名称。三维布局、坐标、路线与旧地图存档不回写，几何数据不因上下文投影被整份复制。

## 边界与后续

本版没有建立跨聊天或跨账户共享世界，没有接管世界书，没有改变变量执行器、地图编辑器的写入协议，也没有将剧情保存、旧地图 sidecar 和世界档案合并成跨库原子事务。地图界面仍显示原地图数据，只有生成上下文消费世界投影。已有手动世界事务是当前已确认字段的写入权威。

下一部分将迁移变量／地图写入与页面读取，使旧模块通过统一命令提交，逐步消除双重状态。人物知情、秘密状态与主角视角过滤、远近颗粒度加载、章篇压缩及后台自治仍属于后续阶段。现阶段的权威字段没有玩家知情隔离，不能将本版当作脱密服务。

验证覆盖真实 IDB 确认提交、失败不发布、其他标签页更新、分支切换、账户／聊天隔离、同名歧义、别名与稳定 ID、预算边界、地图投影、原生生成顺序及读取失败停止发送。所有模型及宿主依赖使用测试边界；未宣称真实 TauriTavern 实聊验证。
