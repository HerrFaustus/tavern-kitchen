# 下一步开发方向：精简后的世界状态与剧情记忆路线

确认日期：2026-11-05；2026-11-14 更新至 `0.2.32` 本地验收版。精简架构的五项代码收尾已完成，真机项目见第 3 节。

## 1. 当前已实现基线（0.2.32）

在 `0.2.21–0.2.32` 期间，以下核心机制已在源码与离线／无头浏览器回归中落地（实装验证详见[验证记录](VALIDATION.md)）：

1. **统一世界内核、每轮来源与同轮提交**：
   - 地图、交易、属性、认知与剧情记录均接入统一世界档案与来源凭据；旧变量系统已完整删除。
   - 独立更新读取当前世界、最近原文、分层摘要与本轮执行回执，接近上限时将不活跃的远方实体降为索引，在同次模型请求中输出 `summary`、`memoryTags`、`storyUpdates` 与 `worldUpdate`；明确且无冲突的关联组自动提交，不确定项或冲突保留给人工核对、修改或拒绝（见[提交与自动确认](WORLD-PROPOSAL-REVIEW.md)）。
2. **可逆递归压缩树与剧情线脉络合流**：
   - 已实装 `L0 → L1 → L2 → L3+` 可逆分层摘要树、故事相对时间与新近优先历史预算分配；常规原文召回只保留单一原文块候选池（向量 + 关键词，Embedding 缺失或失败时自动保留关键词检索）。
   - `modules/story-state/plot-lines.js` 提取并汇总各剧情线累计脉络 `summary`、轮次轨迹 `beats`、涉及人物 `characters` 与当前焦点 `nextFocus`；压缩层同步传播并合并 `plotLineSnapshots`，`ReviseRoundSummary` 对失效引文发出警告并重算。
3. **后台编剧局部重算与提示词后台化**：
   - `modules/story-planner/` 以**人物（`characters`）、剧情线（`plotLines`）、局势（`situations`）**为实体生成 `global` 与 `chapter` 两份札记，支持单实体/字段级 `staleTargets` 失效标定与局部增量重写（换章、切分支或超 `180000` 字符预算自动回退整章重算；见[编剧与剧情线协同机制](story-planner.md)）。
   - 全部提示词设置已从前端下线并收口为后端只读常量；工作台界面与弹窗已统一为宿主原生控件与主题变量。
4. **基础防剧透与失效阻断**：
   - `管理员私有/` 私有字段已在正文上下文与编剧章节札记中拦截过滤；`knowledge` 记录区分 `known`（已知）、`believed`（相信／误解）与 `uncertain`（怀疑），`presence` 区分四档在场状态。
   - 切换分支、编辑或删除旧楼、撤回摘要会立即使过期摘要与札记失活，避免陈旧稿件污染新分支。

## 2. 架构瘦身决策（已取消或简化的设计）

为避免过度设计带来不必要的实现复杂度、维护负担与额外模型消耗，**2026-11-14 起确认取消或简化以下原规划设计**：

| 原规划项目 | 决策 | 简化方案／说明 |
| --- | --- | --- |
| 多作家竞争、主编裁决、四入口（开局/章末/篇末/重大冲击）与三层札记（全局/本篇/本章） | **删除** | 不再作为开发目标；最多维持单一后台编剧，并支持后续按需继续瘦身。 |
| 后台人物自主演化循环（离场 NPC 自己过日子）与空间远粗近细动态加载 | **删除** | 不引入脱离对话轮次的后台事件循环或空间 LOD 生成；无本轮依据的远方对象保持静态归档。 |
| 世界书一次性全量接管、独立跨轴事件账本重写、一次随机命运骰 | **删除** | 不开发整本世界书一次性迁移工具与独立新命运骰工程；保留现有世界提交回执与上游检定机制现状。 |
| 超 20 万字符的多轮“分区分页全视读取协议”（目录 + 分页 + 已读/未读状态表 + 修改前二次拉旧值） | **大幅简化** | 不引入分页读写状态机；超过 `UPDATE_INPUT_LIMIT`（当前 `200_000` 字符）时改用轻量活跃度/相关性裁剪冷门远方细节，绝不臆测删改未完整展示对象。 |
| 全链路自动改写式“知情裁剪”（对摘要正文、标题、人物名、引用、计数、地图标签与检索片段做多视角脱敏重写） | **大幅简化** | 放弃多视角自动重写投影；继续沿用 `管理员私有/` 阻断与 `knowledge` 记录约束提示词，仅补齐轻量视角边界与主角关键状态常驻保护。 |
| 历史修改后的精确局部子树、向量分片与余额账本同步拼接修补 | **大幅简化** | 不实现跨摘要树和账本的精确局部拼接修补；沿用已有失效阻断与分支隔离，修订旧楼后按现有队列顺序重跑受影响区间即可。 |
| 五分项独立成本统计面板与重型长测基建 | **大幅简化** | 不单独建设整理/压缩/编剧/检索/推演五分项计费面板与全套指标基建；保留基础模型调用次数、耗时、报错日志与核心场景回归即可。 |
| 现有单后台编剧三段式实体札记与自动重算 | **收口为手动/轻量可选** | 0.2.32 默认手动更新，生成前自动更新由用户在编剧设置中启用。 |

## 3. 0.2.32 代码收尾与真机验收

### 缺口 1（P0）已完成 · 手动更新章节札记

编剧设置常驻「立即生成／更新札记」和「生成前自动更新章节札记」。自动更新默认关闭，打开编剧页只读取当前分支。正文生成前只复用有效的章节稿，超过上下文 25% 或前提失效时跳过本次注入。手动按钮复用已有编剧与失败重试逻辑，自动模式继续在生成前按需更新。

### 缺口 2（P0）已完成 · 统一模型调用统计

`generateFeatureText` 按 `feature` 统计调用数、失败数、累计毫秒、最近错误和完成时间，并累计供应商返回的可识别 token 用量。取消计入失败。API 页显示本次会话的总调用、失败与耗时，可复制分项和最近 100 条明细，也可清空。明细只保存功能名、时间、数值和脱敏的错误类别，刷新页面后重新计数。

### 缺口 3（P1）已完成 · 主角状态与角色知情边界

正文先为时钟和主角的开放计划、目标分配剧情状态预算，再填悬念与局势。持有、保管、承诺及行动限制优先进入事实与世界字段区。人物认知按持有人和在场状态筛选，明确离场优先于旧位置。即使已有一条认知，在场或重要角色仍会收到关于未记录隐私的提示。

### 缺口 4（P1）已完成 · 大世界输入裁剪

材料接近 200,000 字符时，先收缩重复历史资料，再按本轮参与度、关联与近期变更保留活跃实体。冷门对象仅提供 `{ id, name, kind, aliases, summaryOnly: true }`，编号列入 `manifest.omittedDetailEntityIds`。提案解析与存档校验都会拒绝对索引对象的字段修改。最终序列化请求仍超限时，在调用模型前报告预算不足。

### 缺口 5（P2）已完成 · 保留有效前缀后重记

旧楼删改触发回退且原有撤销链无法直接完成时，总结页显示「从断点重记」。确认框给出能保留的完整摘要前缀和实际起始楼层。确认后清理失效批次及其压缩节点、待审草稿和对应检索尾段，沿用原队列分批补记至最新已完成回复。若改动落在不可拆分的导入基线内，则从第 1 楼重记。已提交的世界效果与原文冲突时，先到「数据 → 世界版本与恢复」核对。

### 缺口 6（待真机）· 真实宿主与在线模型

- 在 SillyTavern 和 TauriTavern 的浅色、深色、紧凑主题与窄屏中检查编剧、API 摘要、从断点重记及确认框。重新打开工作台，核对开关和当前分支札记。
- 用真实独立模型核对同一响应中的 `summary`、`memoryTags`、`storyUpdates`、`worldUpdate` 和 `plotLines`。统一更新时 `storyUpdates` 应为空，认知与计划进入世界提案。记录成功、错误、超时与取消时的调用数、耗时及服务端提供的 usage。
- 用跨压缩轮的长期约定、赊账和物品转移检查召回、余额与执行回执。让玩家改道或提前查明真相，检查过期札记是否停用、离场人物是否守住知情边界。
- 在运行中编辑旧楼、切换候选或世界分支，并中断、重开后继续补记。核对有效前缀、冲突引导、同轮效果防重和另一分支的记录。让 Embedding 失败一次，确认仍可按关键词召回。
- 用接近 20 万字符的远方档案和超限的本轮正文，分别核对裁剪后正常更新与调用前拒绝。真实联调通过后再执行正式发布。

## 4. 精简后仍严格遵守的核心不变量

1. **先正文后更新**：每次正文生成完成后再独立触发更新，不恢复随正文自动总结提取协议。
2. **当前世界为准、回执防重**：当前已确认的世界字段与持有关系是状态权威，历史总结描述不覆盖后续合法更新；已执行回执不得重复扣款、移动或重复触发同一效果。
3. **来源与分支隔离**：所有总结、提案、世界版本与编剧札记均绑定聊天与世界分支；失败或未确认前不推进已确认覆盖位置。
4. **未完整展示不擅改**：无论超限裁剪还是视图筛选，未完整提供的冷门对象不得仅凭未展示而提议删除或覆写。
5. **可追溯文档边界**：架构概览见[记忆架构路线图](MEMORY-ARCHITECTURE-ROADMAP.md)与[简化记忆结构边界](SIMPLIFIED-MEMORY.md)，验证口径以[验证记录](VALIDATION.md)为准。
