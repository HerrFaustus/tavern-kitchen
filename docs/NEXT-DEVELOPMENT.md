# 下一步开发方向：世界状态、剧情记忆与独立更新

确认日期：2026-11-05。当前实现基线：本地酒馆后厨 0.2.21。

本文整理已确认的产品方向、实施顺序与验收要求。目标是持续提供连贯的故事背景、按需找回细节并维护一致的当前世界。独立总结触发方式已调整，地图读写已接入世界内核，旧变量系统已完整删除；每轮来源与执行回执已有基础，0.2.18 接通完整当前世界输入和同请求生成摘要／变化提案。0.2.19 收敛为同次整理产出摘要、标签和提案，原文块作为唯一活动向量对象，停用独立 L0 和场景／互动／事件向量维护。0.2.20 接通人工处理，0.2.21 进一步接通同轮原子提交和保守自动确认：明确且无冲突的关联组自动写入，其他项保留人工修改、拒绝。来源、版本、逐目标效果防重和原提案继续保留。容量处理、来源摘要树和完整双轴注入仍待完成。现状见 [README](../README.md)、[验证记录](VALIDATION.md)及[架构路线](MEMORY-ARCHITECTURE-ROADMAP.md)。

## 0 已确认的简化实施方向

采用“原文、剧情摘要、当前世界、原文检索”四部分。场景与互动信息并入逐轮摘要、标签和世界提案；关系与因果仍保留，检索不再靠图扩散维护另一套状态。原文召回融合关键词与向量候选，最多做一遍可选重排；早期剧情背景独立于检索命中。标签沿用同批来源凭据，不增加第二套消息、版本或效果身份。具体已实现和未实现边界见[简化记忆结构](SIMPLIFIED-MEMORY.md)。

## 1 已确认的注入结构

正文生成与独立更新使用两个用途不同的上下文包。

| 用途 | 横向：世界状态 | 纵向：剧情经历 |
| --- | --- | --- |
| 正文生成 | 主角相关的当前状态始终注入；其他对象按本轮相关性注入；其余保存在世界中。所有内容遵循选定叙事视角与知情范围。 | 最近几轮原文始终注入；早期经历以逐层概括后的总结持续提供故事背景；相关的早期原文按需补充。 |
| 独立更新 | 以管理员视角读取整个当前世界状态，包含幕后信息、各方认知、计划、候选及来源性质；初期默认直接提供完整快照。 | 最近原文包含本轮已完成内容，并提供覆盖早期经历的分层总结；核对细节时可回查旧原文。层级形式与正文相近，访问范围按管理员用途确定。 |

关键区别是：正文按当前叙事需要看到世界，独立更新以全视材料核对变化。纵向的早期总结是持续的故事背景，不能全部退化成“相似度命中才出现”的零散记忆。

已确认的其他规则：

- 每次正文生成 session 完成后，再独立更新。这里的 session 指一次正文回复生成，不是整段聊天结束。
- 暂时停用随正文总结协议与自动提取；后续开发不自动恢复这个入口。
- 当前世界状态表达“现在怎样”，历史原文与总结表达“当时发生过什么”。历史描述不覆盖已经合法更新的当前字段。
- 全视读取用于对账和一致性检查。写入依据限于本轮事件、已执行结果及明确到期的后台任务；不因读到一个对象就擅自演化它。
- 后台掌握的信息与人物知情分别记录。全视更新结果须经视图筛选后才能用于正文、角色决策或玩家界面。

最近原文轮数、压缩阈值、预算及相关性权重尚未锁定，须通过样例测量；不把柏宝书的默认数量直接当作后厨的产品要求。

## 2 横向与纵向共用来源

每次已发生的事情保存可追溯的原始来源与事件身份。世界状态、人物认知、剧情摘要、地图和状态栏分别从同一批已确认记录形成投影。事实、传闻、猜测、计划和创作提案保持各自性质。

主角相关的常驻状态包含当前身份与能力、资源与持有物、所在地、正在承担的任务、承诺和必要约束。具体字段清单由世界数据契约定义，不能只因本轮没有点名就被相关性排序挤掉；主角相关的旧经历仍归纵向组织。关联其他人物时，也不能顺带公开其全部秘密。

人物、地点、组织、物品和关系使用稳定实体 ID。名称与别名用于查找，明确且唯一时可以关联；同名歧义保留待核对，不能让不同名字、不同模块或不同摘要产生多套身份。

地图写入已接入世界命令；金币、位置、归属等直接使用世界实体字段，不再保留独立变量系统、旧指令或变量路径绑定。每轮来源、消息／候选身份和已执行效果回执已接入全视输入及人工／自动提交。完整性清单继续标明实际覆盖的状态与历史材料；保留的旧原始档案不作为活动状态来源。

## 3 正文上下文如何组装

横向先按叙事视角建立可访问范围，再装入主角常驻状态与本轮相关对象。人物在场、当前行动、物品归属、空间联系、任务、承诺及期限都可以产生相关性；未注入的对象仍然存在，冷却状态也不等于被删除。

纵向按时间远近选择表达粒度：

**较早的篇级概括 → 较近的章节总结 → 最近的阶段摘要 → 最近几轮原文。**

每段历史默认选择一份合适粒度的表示，记录其覆盖范围，避免父摘要、子摘要和近期全文反复占用上下文。回捞的旧原文可以与概括共同出现，作为本轮所需细节，并明确来源。

高阶总结持续覆盖允许访问的早期经历，保留主要因果、人物变化、仍有效的承诺与未决问题。词法和向量召回用于补充细节，不负责决定某段历史是否从故事主线中消失。

知情筛选适用于摘要正文、标题、人物名、引用、计数、地图标签及检索片段。面向管理员的完整摘要不能原样塞入有限视角正文；必要时选择相应视图或拆解到可公开的下层节点。

## 4 独立更新者看到什么

| 上下文部分 | 提供内容 | 用途 |
| --- | --- | --- |
| 本次增量 | 上次成功更新后全部未处理的用户发言与最终正文，通常就是本轮；附消息身份、版本与内容指纹 | 确定本次实际发生的事情与来源，覆盖失败后的积压内容 |
| 最近原文 | 本轮及相邻几轮的完整有效原文 | 理解指代、动作承接、对话对象与当前场景 |
| 早期分层总结 | 覆盖之前经历的适当层级总结，携带时间、来源与事实性质 | 理解长期因果和人物经历；保留故事主线 |
| 完整世界快照 | 当前世界全部已生成状态，包括主角、其他实体、关系、幕后信息、各方认知、计划、未决事项和不同性质的记录 | 对照旧值，检查关联变化、身份与冲突 |
| 本轮执行回执 | 已提交的交易、资源与字段更新、位置变化、骰子结果、后台任务及对应世界版本 | 识别已经落账的结果，避免再次扣款、移动或抽样 |
| 适用规则 | 世界与角色设定、字段含义与约束、更新条件及输出要求 | 判断哪些内容能成为事实、哪些应保留为候选 |
| 必要旧原文 | 对旧事件有指代、摘要不够精确或发生冲突时，按需查询的原始材料 | 核实金额、期限、原话、因果和角色知情来源 |

全视世界指完整的当前状态语义，不要求重复附上全部历史日志和模型二进制资产；这些材料通过稳定引用查询。只保留宏观状态的远方仍以已有宏观事实表示，全视不会凭空细化未生成区域。

“和下一轮正文注入差不多”指纵向材料的组织方式相近。更新者先读取本次增量与一致版本的基线，成功提交后，下一轮正文才消费更新后的世界和记忆。不能用未来状态核对过去，也不能把正文的有限视角筛选当作更新者的全视边界。

## 5 全视读取与容量策略

初期中小世界默认向独立更新模型直接提供完整世界快照，不按主角视角或本轮相关性删掉其他状态。这是本次已确定的默认方向。

世界增长后，可改为全局概况加分区详细读取，保持全世界访问权限。上下文清单须记录读取模式、世界版本、已读分区、未读分区和完整性；全局概况不等于每个字段都已读取。涉及某个分区或字段的修改，必须先取得该版本的准确旧值与约束。

预算不足时拆分读取或任务，明确保存未完成状态。不能静默截断后仍声称全量核对成功，也不能把未读、未知或不存在当作同一回事。分区读取只改变容量策略，不扩大任何 NPC 或正文任务的知情权限。

## 6 每轮更新的产出与提交

目标是把常规的一轮整理合并在一次独立模型请求中，同时产出：

1. 本楼或本次增量的叙事摘要。
2. 人物、地点、时间和关键词标签；场景与互动重点并入摘要，不另建活动检索卡。
3. 世界字段、关系和实体变化的提案。
4. 人物知情变化及其证据。
5. 任务、计划、承诺和悬念的推进、完成或失效记录。
6. 冲突、缺失依据、待核对事项，以及必要的场景或章节边界候选。

0.2.19 已将现有剧情总结与独立 L0 提取的重复语义分析收敛到这一请求。Embedding、重排和必要的历史核对另按任务执行；“一次整理请求”不是保证所有故障恢复与长篇压缩都只需一个网络请求。

模型提出变化，脚本校验实体引用、旧值、数量、规则、版本、来源与权限，由世界内核提交。已执行回执只引用和补记经过，不再执行其效果。没有依据的变化进入待核对项，不能只凭模型置信度成为事实。

0.2.21 已接通同轮关联组和保守自动确认。原总结请求增加关联组与明确程度；来源、世界内容、旧值及执行回执全部匹配且组内无不确定项时，一笔事务提交本轮可自动处理的变化。买卖的金币与归属继续做依赖合并。其他项保留人工一起核对、修改或拒绝；老提案不补造明确程度，多轮积压或冲突不勉强自动提交。具体规则见[提交契约](WORLD-PROPOSAL-REVIEW.md)。

重要行动的规则与命运裁定继续使用原有目标协议，在叙事交付前固定必要结果。事后整理不重新掷骰，也不把已交付的确定结果悄悄改成另一种发展。发现正文与已提交结果冲突时，保存冲突并走明确恢复或修订流程。

## 7 版本、进度与失败恢复

每次更新固定世界、分支、世界版本、记忆版本、本次消息范围、最终候选回复身份与内容指纹，并携带上次成功处理位置。

基线世界快照可以已经包含本轮由脚本提交的结果，此时必须附带对应回执。未执行的提案与已落账结果分别处理，不能为了“更新前状态”而忽略已经合法提交的事实。

在确认保存前重新核对来源与版本。切换聊天、切换候选、修改原文、选择分支或发生冲突写入后，旧结果不得落到新状态；需要取消、重新读取或重算。

只有状态与记忆已按一致性协议确认，才能推进成功处理位置。失败后从上次确认位置恢复；重复完成通知和请求重试复用同一提交身份。分批处理积压时，只推进已经确认的连续范围。

世界数据库与宿主聊天文件仍可能跨持久化边界，使用提交回执、交付记录与恢复流程保证可核对；不能把多个独立保存冒充跨库原子事务。下一轮构建上下文时，必需的状态或记忆若尚未确认，应等待确认或进入显式恢复；可重建的向量维护可以延后。

## 8 分层总结与历史修改

借鉴柏宝书的来源树：楼层记录作为下层依据，阶段、章和篇的总结通过子节点引用组织。保留原文、下层摘要与来源版本，压缩只改变叙事表达，不重复提交世界变化。

每个节点至少记录身份、层级或叙事单元、子节点、覆盖消息范围、故事时间范围、分支、来源版本、事实性质、访问范围和有效状态。字段名称在实现契约中确定。

阶段摘要可以在材料积累后滚动生成。章节和篇的边界依据实际叙事收束；固定数量压缩不能冒充自然章末，也不会独立触发编剧室或推进世界时间。压缩参数需单独验证。

修改、重摘、删除、番外切换或候选回复变化时，沿来源依赖标记受影响的摘要和索引失效，保留其他完好的分支。历史变化还须按世界回退规则处理相应提交；不能仅修正文案而留下不一致的余额或物品归属。旧分支和原始回执继续可追溯。

模型生成的高阶总结可能丢失细节，因此当前金额、期限、归属和角色知情从世界状态或原始证据核对；不能只从一段概括推算。

## 9 召回保留与改造范围

活动检索只保留原文块向量，以关键词和人物／地点／时间标签补充候选。场景、互动和事件的信息进入逐轮摘要及世界变化提案；人物关系、剧情因果继续保存，不再为召回维护独立 S／R／事件向量或图扩散流程。

先校验来源、分支、版本和有效性，再对一个原文候选池排名，至多做一遍可选重排。早期摘要背景独立于检索命中装入；最近可见原文和明确省略的楼层不重复召回。正文访问范围最终由 P4 的知情视图约束，不能把检索分数当作访问权限。

Embedding 是可重建索引，总结是叙事记录，召回是材料选择，当前世界是状态权威。向量缺失、模型变化或请求失败时保留关键词检索，关键当前状态不靠相似度猜取。索引维护继续绑定内容与模型指纹，历史修改会作废相应结果。

旧算法、场景卡与向量暂作历史存档和离线对照，当前配置不切回旧检索链。小白X与柏宝书的来源比较见[源码调研](../../docs/小白X与柏宝书记忆机制对比.md)。

## 10 建议实施顺序

P1 基础已接通；P2 进行中。0.2.18 接通完整当前世界、已执行回执和同请求摘要／提案；0.2.19 简化整理与原文召回；0.2.20 接通人工核对，0.2.21 接通同轮事务和明确变化自动确认。现有早期记忆如实标为尚无高阶摘要树，超预算停止。容量处理与真实宿主完整联调尚未完成，因此 P2 不标为全部交付；P3–P5 待实现。当前契约见[提交与自动确认](WORLD-PROPOSAL-REVIEW.md)。

| 顺序 | 开发任务 | 进入下一项前应具备的结果 |
| --- | --- | --- |
| P1（基础已接通） | 统一每轮来源、消息与实体身份、已执行回执和世界命令；地图使用同一状态，删除旧变量路线 | 来源账本、确认交付、效果防重和分支隔离已有回归；自动历史依赖修复仍待后续阶段 |
| P2（进行中） | 全视输入、同请求摘要／标签／提案、原文单池召回和人工处理已接入；0.2.21 接通同轮提交及明确变化自动确认；容量处理待完善 | 自动回归覆盖同轮原子性、自动／人工分流及防重；分区读取与真实宿主完整联调仍待验收 |
| P3 | 建立来源树、阶段／章／篇压缩和历史依赖修复 | 高阶总结持续覆盖早期经历，下层保留，受影响部分可局部拆解与重建 |
| P4 | 完成正文双轴注入、知情视图及相关旧原文补充 | 主角当前状态与历史主线常驻，其他状态和细节按需进入，秘密不会从摘要旁路泄露 |
| P5 | 用真实宿主和固定故事开展端到端验证，记录成本与召回表现 | 重启、编辑、回退、分支、模型故障与长聊通过相同样例，形成可复现验收记录 |

版本、知情、回退和失败恢复贯穿 P1–P5，不等到最后补做。P5 是完整联调关口，不代表前面可以省略各自验证。上述任务细化原路线第二至第四阶段；编剧室、后台人物和原生宿主的长期方向继续保留。

P2 先固定分层背景的读取接口，并如实记录当时可用的历史材料与缺失范围；P3 建立摘要树后再完成完整背景覆盖的验收。不能把现有单份增量总结或占位节点标成已经具备完整章篇压缩。

## 11 增补验收

以下 N01–N15 尚未执行完整产品验收；已完成的地图、世界内核与移除回归不代表完整双轴上下文或全视更新通过。

| 编号 | 场景 | 必须观察到的结果 |
| --- | --- | --- |
| N01 | 本轮未提及主角已持有的关键物品或正在承担的承诺 | 符合叙事视角的主角常驻状态仍进入正文上下文 |
| N02 | 本轮涉及某个其他人物，世界中还有大量无关对象 | 正文获得相关且可知的状态；无关对象保留在库中 |
| N03 | 很早的一段经历没有被本轮关键词命中 | 其高阶概括仍作为合法故事背景被覆盖；不因未命中而丢失主线 |
| N04 | 同一时间段同时有篇、章、阶段摘要和原文 | 默认背景选择合适粒度且覆盖可核对，不重复堆叠所有层级 |
| N05 | 旧承诺的准确原话成为本轮重点 | 在概括之外找回对应原文，来源与故事时间正确 |
| N06 | 独立更新读取包含幕后秘密的世界 | 更新者全视可读；正文、未获知秘密的 NPC、玩家搜索和摘要视图不泄露 |
| N07 | 全视材料包含无关远方人物和未细化地区 | 无依据的对象不被改动，不生成远方细节，不凭调用次数推进世界 |
| N08 | 原本欠15金币，本轮归还10金币，交易已先提交 | 当前欠款保持5金币，只补叙事记录，不再次付款；旧“欠15”仍可作为历史 |
| N09 | 独立更新失败后又积累多轮正文 | 从最后确认位置连续处理全部遗漏范围；重试不漏记、不重复记账 |
| N10 | 模型运行时编辑原文、换 swipe、切聊天或分支 | 旧结果不写入新来源，其他聊天或分支不受污染 |
| N11 | 第40轮还款10改成8 | 对应历史路径欠款变为7；相关摘要与索引修复，无关子树和旧分支保留 |
| N12 | 章篇压缩和摘要重建反复执行 | 世界字段与骰子结果不重复应用，来源仍能回到下层记录 |
| N13 | 完整世界超出本次上下文预算 | 明确分区读取与未完成范围；未读字段不被修改，不以截断包冒充全量核对 |
| N14 | 用户在更新尚未确认时请求下一轮，或 Embedding 失败 | 必需状态等待确认或恢复，迟到任务不覆盖新状态；可用基础检索继续工作 |
| N15 | 同一回复收到重复结束通知 | 常规整理不因重复通知而重复调用或提交；任务、模型请求、压缩及检索费用分别统计 |

## 12 连续故事样例

第10轮，主角赊购20金币的铁剑，先付5金币，约定下次见面结清。独立更新保存本轮摘要、标签、变化提案及来源，并经统一交易记录“铁剑归主角，欠款15金币”。

第40轮，主角通过信使偿还10金币。若脚本已经提交交易，更新者读取完整世界与本轮回执，补记经过，当前欠款为5金币；若尚未执行，则提出待校验的交易变化。两种路径都只能结算一次。

中间经历逐步整理成阶段、章和篇的总结，主线保留赊购、部分还款及仍未兑现的承诺，原文继续保留。

第100轮重返铁匠铺时，正文得到主角及铁匠相关的当前状态、覆盖早期经历的总结和按需回捞的约定原文。模型据此知道“当初欠15、已经还10、现在还欠5”。

若把第40轮还款改为8金币，按历史编辑规则建立或修订对应路径，欠款成为7金币；只修复依赖该变化的状态、摘要和索引。该样例用于验证当前值、历史描述、压缩、检索和回退能否保持一致。

## 13 当前边界与待定参数

当前本地版本 0.2.21 已具备每轮来源、已确认摘要交付、逐目标幂等回执，以及管理员全视输入与同请求摘要／世界提案。旧变量保持删除，世界字段与地图由统一内核维护。默认每次正文完成后独立总结，间隔1楼、延迟0楼；明确且无冲突的关联组自动一起写入，其他项在世界管理中一起核对、修改或拒绝。独立 L0 与场景／互动／事件向量维护已停用，正文使用单个原文候选池，现有早期摘要背景独立注入；尚无阶段／章／篇摘要树。旧摘要不补造来源或自动批准信息；世界效果来源冲突先停止核对，后续人工状态不自动撤销。容量分区、来源摘要树、正文双轴视图和真实宿主完整联调仍待完成。

待通过原型确定：最近原文保留轮数、阶段压缩时机、摘要篇幅、全量与分区读取的预算界限、检索条数和权重、每轮耗时与费用目标、源记录及摘要节点的最终 Schema。自然章篇边界、主角状态常驻、历史概括常驻、全视更新及来源可追溯属于已确定行为，不能因参数尚未定而省略。

本文同时记录目标设计与当前实施进度；具体构建和回归结果以[验证记录](VALIDATION.md)为准，本地开发进展不等于已发布更新。
