# 酒馆后厨 0.2.30

本版精简数据页和设置布局，在编剧面板展示当前札记；保留后厨卡、世界版本恢复及来源、防重复机制。

功能板块下区以对应功能命名，如「地图设置」，按需显示模块开关、模型设置、功能设置和提示词设置；没有内容的分组不显示。前三项始终展开，提示词默认折叠；设置区默认占三分之一高度，展开提示词时向上扩展，内部可滚动。


API 和数据采用一体化整页布局；数据集中显示资料概况、后厨卡和世界版本恢复。其他功能板块按上下两部分组织：上方浏览记录，下方集中放开关、演化、频率、手动触发、模型及提示词；展开提示词时设置区向上扩展。API 合并为整页，选择连接后直接配置与测试。


局势页按事态、风物上下展开，各组标题旁可独立开关演化。人物和地图用于浏览自动维护的资料。剧情与局势不再提供搜索框，独立关键词面板与编剧创作偏好已移除；每轮总结的关键词召回标签继续参与召回并可由校对修订。旧局面记录沿用原编号、来源和历史，统一展示为局势。

局势页在有未处理世界变化时显示「待核对的世界变化」，可按关联组确认、修改或拒绝，已变化的基线须重新核对。无法从原文直接核对或可能涉及幕后内容的提案默认隐藏，可主动选择显示。后厨卡导出和导入当前世界分支的编剧札记；旧版导入时误归属聊天的札记会在首次使用时归入当时的世界分支，原记录不删除，后来生成的分支札记优先。已经导出的旧后厨卡如果不含札记，不能从卡内恢复缺失内容。

「数据 → 世界版本与恢复」可从历史版本建立新世界分支，也能切回保留的旧分支。已写入变化的正文来源发生冲突时，先核对来源账本，再提示建议版本。恢复只改变世界分支，不会回退聊天或总结；总结和地图仍可能重新提供资料。札记按分支独立保存，后厨卡只包含导出时的当前分支。


后厨入口位于酒馆顶栏最右。「剧情 → 总结」显示章节、篇目和本轮总结，下方可以调整总结规则、召回、模型和提示词。「世界 → 世界生成」读取开局资料，手动点击才会建档。后续人物、局势与地图仍按各自的演化开关运行。功能面板的模型绑定统一放在底部对应的设置区。总结规则和召回在本页展开，「数据」提供后厨卡导入导出和世界版本恢复，平级面板由上方导航切换。

「编剧」上半区以**人物、剧情线、局势**三类实体为核心展示当前章节札记，按实体列出**点评、走向预测与建议**；全局札记默认折叠并提示可能剧透。查看札记不会额外请求模型；当世界前提或剧情线累计总结推进时会自动标明需要更新。

「剧情 → 剧情线」按进行中、潜在线与已收束整理剧情线，并提供线头统计、`脉络总结`、`最新动态`、`当前焦点`、涉及人物与可展开的多轮`推进轨迹`。每轮总结提取新进展与逐字依据并累计汇总后，直接移交编剧作为下游规划材料；校对删去依据或撤回该轮时同步重算。旧聊天可从已有计划、悬念和事态开始。

API 整页布局、连接切换与保存可运行 node scripts/check-api-layout.mjs 验证。统一下区的三分之一高度、跨框架设置和关闭后重新启用可运行 node scripts/check-workspace-layout.mjs 验证。

界面回归可在构建后运行 `node scripts/check-summary-footer.mjs`，也可以在命令末尾传入本机插件目录验证安装版本。脚本用 Playwright 的 Chromium 在后台打开独立测试聊天页面，并检查人物切换、关系词条和总结页控件的恢复。可通过 `PLAYWRIGHT_MODULE` 指定已有 Playwright 安装，通过 `CHROMIUM_BIN` 指定 Chrome 或 Edge。

世界变化、世界版本恢复和后厨卡的后台浏览器回归为 `node scripts/check-proposal-workspace.mjs`；命令末尾可传入本机插件目录验证安装版本。它使用隔离的虚构聊天与浏览器数据库，检查整组确认、修改、拒绝、来源回执、敏感内容默认隐藏、世界分支恢复和切换、后厨卡及旧札记恢复，不读取或改动真实聊天。世界恢复和后厨卡的单元回归为 `node --import tsx --test modules/world-records/recovery-panel.test.js modules/kitchen-data/card.test.js`。

## 本版保留什么

| 能力 | 当前实现 |
| --- | --- |
| 剧情 | 正文回复完成后独立总结、场景锚点、可编辑楼尾清单、分层记忆、人物与事件记录、维护与备份 |
| 召回 | 关键词检索、向量检索及召回上下文组装；Embedding 需要自行配置 |
| 规划 | 单作家后台编写全局与章节札记，正文仅读取当前章节成品 |
| 世界字段 | 金币、归属、位置等由统一世界内核校验、提交与回退；没有独立变量面板或旧指令执行器 |
| 地图 | 地点词条、可感知要素、有方向的连接；页面读取与保存接入统一世界事务和历史分支 |
| 世界档案 | 独立实体身份、事实与候选、来源映射、事件提交、交易、历史分支及导入导出；旧模块仍逐步接入 |
| 后台世界 | 原有世界分区、背景维护与注入 |
| 基础设施 | 宿主桥接、API 预设、后台任务协调、确认写入、聊天分支与保存恢复 |

扩展入口先创建按钮和面板框架，再加载设置与功能，不等待模块初始化；首次打开进入“总览”。工具栏晚到或被重建时恢复同一入口。所有后厨页面固定跟随酒馆配色、字体、透明度与动效，不再提供独立主题选择；旧后厨主题选择不再生效。宿主决定扩展脚本加载时点，因此无法承诺与原生 HTML 按钮在同一帧出现。

内置教程、使用说明页和部署指南已移除。内页按钮、输入框、复选框与分组标题统一采用酒馆原生控件外观；规划页使用顶部按钮导航，保留必要的字段说明和操作状态。

顶部入口顺序为 **用户管理 → 角色管理 → 后厨**，后厨使用酒馆自带的实心门形图标。桌面面板沿用原生右栏宽度，右边缘止于聊天区；单栏手机布局沿用宿主抽屉；无展开工作区按钮。标题、导航使用原生控件，背景、透明度和模糊由宿主面板统一承担。一级导航为 **主角／世界／剧情／编剧／API**。世界包含人物、地图、局势和世界生成。剧情包含总结、悬念、剧情线和校对。「API」用于管理和测试连接与模型。各功能面板下方有启用开关。关闭后收起内容，保留导航和开关，随时可以原处恢复。调用模型的面板在下方选择 API，展开“提示词”可编辑、保存或恢复默认。修改从下次请求生效。人物页直接展示档案、关系词条、认知与在场度；称号和别名归入身份属性，主名及指向按已确认身份自动识别，同名歧义保留各自稳定编号；局势页同时展示结构化局面与旧事实分组。旧关系链接仍进入人物页。见[工作台说明](docs/WORKSPACE-UI.md)。

角色回复下方的总结默认收起，展开可编辑时间、地点、摘要、场景锚点与变化条目。收起状态只保留摘要预览和状态；尚无摘要时显示“总结本楼”，通过副 API 生成单楼摘要；已有摘要时显示“重新总结”，确认后覆盖。待审查时展开后的主操作是“确认写入”，番外、重新提取、查看剧情和删除摘要收在“更多”。锚点支持修改场景叙述、地点和最多三组发起者／行动／对象，或删除整张卡。提取只重读本楼原始回复；覆盖人工修改前需确认，取消确认保留未保存输入。缺失、输出未完成或格式错误会显示状态；正文回复完成后按自动总结设置调用独立总结接口；“总结本楼／重新总结”另行提供单楼手动更新。旧区间总结保留实际范围，通过剧情资料编辑。

0.2.4 将模型接口统一为命名 API 配置库，剧情、规划、世界／地图和召回各自选择配置。支持复制酒馆主接口或只复制连接后另选模型；旧设置自动迁移。详见[配置说明](docs/api-profiles.md)。

### 0.2.1 历史设计

**世界 → 更多 → 世界管理**可查看对象和已确认状态，核对待处理变化，查阅历史版本。人物、局势、设定与地图是世界的分类视图；总览同时读取剧情和世界。旧变量页已移除。

0.2.14 起地图页面与编辑接入世界存档；0.2.16 已删除旧变量执行系统，不再进行变量树与实体字段的双向绑定。世界书仍由宿主读取，自动识别并结算叙事交易仍待后续开发。完整边界见[世界状态设计](docs/WORLD-ARCHIVE.md)。

## 安装与开始

1. 在 SillyTavern 的“扩展”页面点击“安装扩展”，粘贴 `https://github.com/HerrFaustus/tavern-kitchen` 并安装。
2. 仓库已包含 `dist/` 构建产物，安装时无需运行 Node 或 pnpm；后续通过酒馆的扩展更新功能获取更新。
3. 刷新酒馆，点击顶部菜单栏的后厨门形图标。扩展设置里也保留“打开后厨”入口。也可下载仓库 ZIP，把完整目录以 `tavern-kitchen` 为名放到 `public/scripts/extensions/third-party/` 下。
4. 进入所需面板，在面板下方启用该功能，开关即时生效。“剧情 → 总结”的自动总结默认在每次正文回复完成后独立总结，可调整自动触发时机；向量召回与总结模型也在总结下方选择。打开“剧情 → 校对”可手动查证原文、查看校对记录、选择模型或设置校对提示词。新配置默认每 5 轮正文校对一次，可调整为 1–100 轮或关闭自动校对。校对者依据剧情收束情况决定是否调用阶段／章节总结；在“剧情 → 总结”可逐层展开查看总结。“剧情 → 总结 → 总结提示词”可分别编辑本轮、篇目和章节提示词。默认保留最近 5 轮原文，更早已总结的轮次隐藏并注入摘要。保留轮数及早期原文按需召回可在总结下方调整。“API”用于创建、管理和测试命名连接与模型；编剧模型在“编剧”底部的“模型设置”选择，世界／地图模型在对应板块选择。人物、局势与地图共用世界后台 API，世界生成可单独绑定。

记忆的消息快捷按钮也会打开对应标签，不再另起独立主面板。收起工作台再打开会回到上次标签；切换聊天会收起，避免把旧聊天视图误认成当前聊天。剧情记忆和原文检索默认启用，每次正文完成后独立更新到最新已完成回复，积压自动分批。配置向量模型后自动维护原文向量，未配置时仍可用关键词检索；独立 L0 提取保持停用。地图自动维护、世界后台、骰子自动检定及规划器继续沿用原有开关。API 由各模块设置控制。

0.2.12 重新运行了 API 设置、板块开关、世界“更多”、剧情设置、总览、世界总览和世界管理的离线浏览器截图检查；楼尾总结与扩展面板沿用 0.2.11 的检查，地图设置沿用 0.2.10 的检查。没有重新运行真实模型联调。宿主静态导入与资源校验使用本地固定的 SillyTavern 1.19.0 源码；1.14.0／1.18.0 的部分真实保存函数用于自动测试。没有向用户正在使用的酒馆目录部署，也没有调用付费模型。**尚未完成实际酒馆浏览器及真实模型对话联调，不将本包标为稳定版。** 其他 Tavern 框架需另行验证适配。

## 后厨卡

「数据」板块提供后厨卡导入、导出和世界版本恢复。后厨卡只包含当前聊天的总结及来源历史、世界人物／地图／局势和编剧札记，不包含功能开关、提示词、API 连接或密钥。向量缓存不写进卡，导入后按当前模型重新建立。旧版总结包和向量备份入口已移除，原有服务器备份文件不会自动删除。导入前会提示替换当前聊天数据；同原文保留来源、修订及分层历史，不同原文采用可移植总结基线并归档原来源，不把旧楼层证据冒认为当前原文。导入分支先暂存，宿主确认保存后才统一启用。

后台验证：`node --import tsx --test modules/kitchen-data/card.test.js`。界面用无头 Playwright 运行 `node scripts/check-summary-footer.mjs`、`node scripts/check-api-layout.mjs`、`node scripts/check-workspace-layout.mjs`；可通过 `PLAYWRIGHT_MODULE` 和 `CHROMIUM_BIN` 指定现有运行库与浏览器，不占用桌面。

## 开发

需要 Node.js 24 与 pnpm 11.25.0。本次环境的系统 npm 安装不完整，因此改用 pnpm，并提交 `pnpm-lock.yaml`；没有修改系统 npm 或 Git 配置。

```sh
pnpm install --frozen-lockfile --ignore-scripts
pnpm build
pnpm test
pnpm check
python scripts/package.py
```

`build` 执行静态检查、类型检查、打包和宿主资源验证；`check` 还核对版本一致性、构建一致性、回归测试和记忆运行时。首次验证历史宿主保存函数可能下载固定提交；完整外层参考库可供离线宿主接口检查。构建过程不修改宿主源码。

面板开关和提示词可在后台单独验证。运行 `node --import tsx --test core/kitchen-workspace.test.js core/panel-controls.test.js`，覆盖导航、API 绑定与提示词保存、恢复后的请求内容。

测试结论及限制见 [验证记录](docs/VALIDATION.md)，发布步骤见 [发布流程](docs/RELEASING.md)。运行产物在 `dist/`，开发缓存和日志在 `output/`，安装 ZIP 在 `release/`。
