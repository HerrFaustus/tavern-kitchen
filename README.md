## 本版保留什么

| 能力 | 当前实现 |
| --- | --- |
| 剧情 | 正文回复完成后独立总结、场景锚点、可编辑楼尾清单、分层记忆、人物与事件记录、维护与备份 |
| 召回 | 关键词检索、向量检索及召回上下文组装；Embedding 需要自行配置 |
| 规划 | 独立 ENA 规划器及上下文参考；尚非多作家编剧室 |
| 世界字段 | 金币、归属、位置等由统一世界内核校验、提交与回退；没有独立变量面板或旧指令执行器 |
| 地图 | 层级地点、场景编辑、Three.js 三维场景；页面读取与保存接入统一世界事务和历史分支 |
| 世界档案 | 独立实体身份、事实与候选、来源映射、事件提交、交易、历史分支及导入导出；旧模块仍逐步接入 |
| 后台世界 | 原有世界分区、背景维护与注入 |
| 骰子 | 原有行动检定与低概率遭遇；删除付费重掷与钱包依赖，重置人物属性不收费 |
| 基础设施 | 宿主桥接、API 预设、后台任务协调、确认写入、聊天分支与保存恢复 |

扩展入口先创建按钮和面板框架，再加载设置与功能，不等待模块初始化；首次打开进入“总览”。工具栏晚到或被重建时恢复同一入口。所有后厨页面固定跟随酒馆配色、字体、透明度与动效，不再提供独立主题选择；旧后厨主题选择不再生效。宿主决定扩展脚本加载时点，因此无法承诺与原生 HTML 按钮在同一帧出现。

内置教程、使用说明页和部署指南已移除。内页按钮、输入框、复选框与分组标题统一采用酒馆原生控件外观；规划页使用顶部按钮导航，保留必要的字段说明和操作状态。

顶部入口顺序为 **用户管理 → 后厨 → 角色管理**，后厨使用酒馆自带的实心门形图标。面板沿用原生右侧栏位置，桌面贴顶并自上而下展开，窄屏从工具栏下方展开；无展开工作区按钮。标题、导航使用原生控件，背景、透明度和模糊由宿主面板统一承担。一级导航为 **总览／世界／剧情／规划／API 设置**：世界下保留世界状态、局势、人物和地图，设定、后台演化与世界管理收进“更多”；剧情下为事件时间线和剧情设置；API 设置只管理连接与模型。功能开关放在各功能板块顶部，切换后保存并刷新。人物页保留档案与关系图，并展示认知与在场度；局势页同时展示结构化局面与旧事实分组。旧关系链接仍进入人物页。见[工作台说明](docs/WORKSPACE-UI.md)。

角色回复下方的总结默认收起，展开可编辑时间、地点、摘要、场景锚点与变化条目。收起状态只保留摘要预览和状态；尚无摘要时显示“总结本楼”，通过副 API 生成单楼摘要；已有摘要时显示“重新总结”，确认后覆盖。待审查时展开后的主操作是“确认写入”，番外、重新提取、查看剧情和删除摘要收在“更多”。锚点支持修改场景叙述、地点和最多三组发起者／行动／对象，或删除整张卡。提取只重读本楼原始回复；覆盖人工修改前需确认，取消确认保留未保存输入。缺失、输出未完成或格式错误会显示状态；正文回复完成后按自动总结设置调用独立总结接口；“总结本楼／重新总结”另行提供单楼手动更新。旧区间总结保留实际范围，通过剧情资料编辑。

## 世界状态与总览 0.2.1

**世界就是整个世界状态的入口。** **世界 → 世界状态**汇总对象、已确认状态、待处理记录与近期变化，不保存第二份档案，也不独立调用模型。人物、局势、设定与地图是世界的分类视图；总览同时读取剧情和世界。旧变量页已移除。

新增、修订、来源确认、交易与分支备份集中在 **设置 → 世界管理**。总览和世界管理读取同一份内核状态；原“档案”独立导航已移除，旧链接转到总览。分类页仍在逐步接入统一内核，本版没有将旧存储全部迁移。

已有剧情记录和地图对象在打开总览或世界管理时同步，之后响应原模块的数据通知；不增加模型调用。明确且唯一的名称／别名可以绑定同一身份，歧义对象不自动合并。

来源记录先列为待处理项，确认后才成为当前事实；传闻、认知、计划和创作候选单独保留。可新增对象、编辑名称、登记状态、追溯来源与变更，关联对象可以点开查看。交易同时更新双方金币和物品归属，持有物品列表从归属推导。

存档保存在当前浏览器／应用的 IndexedDB，按角色或群组与聊天身份隔离。存档管理支持完整导出、恢复到新分支与分支切换；历史记录可以从指定版本建立新分支。**这还不是跨设备服务端存档，也不自动跟随宿主聊天回退。**

0.2.14 起地图页面与编辑接入世界存档；0.2.16 已删除旧变量执行系统，不再进行变量树与实体字段的双向绑定。世界书仍由宿主读取，自动识别并结算叙事交易仍待后续开发。完整边界见[世界状态设计](docs/WORLD-ARCHIVE.md)。

## 安装与开始

1. 在 SillyTavern 的“扩展”页面点击“安装扩展”，粘贴 `https://github.com/HerrFaustus/tavern-kitchen` 并安装。
2. 仓库已包含 `dist/` 构建产物，安装时无需运行 Node 或 pnpm；后续通过酒馆的扩展更新功能获取更新。
3. 刷新酒馆，点击顶部菜单栏的后厨门形图标。扩展设置里也保留“打开酒馆后厨”入口。也可下载仓库 ZIP，把完整目录以 `tavern-kitchen` 为名放到 `public/scripts/extensions/third-party/` 下。
4. 在剧情、规划、地图与世界、骰子或 API 设置板块顶部的开关启用对应功能并刷新。“剧情 → 剧情设置 → 总结规则”默认在每次正文回复完成后独立总结，可调整自动触发与范围；向量召回与总结／助手模型也在剧情设置中选择。“API 设置”只创建和管理命名连接与模型；规划模型在“规划 → 剧情规划”选择，世界／地图模型在对应板块选择。再按需启用地图维护、世界后台或骰子。

记忆的消息快捷按钮也会打开对应标签，不再另起独立主面板。收起工作台再打开会回到上次标签；切换聊天会收起，避免把旧聊天视图误认成当前聊天。启用当前聊天的剧情记录后，默认在正文回复完成后独立更新剧情记忆，总结范围包含最新已完成楼层。向量召回开启时，后台 L0 提取与向量维护继续按原流程运行；向量、地图自动维护、世界后台、骰子自动检定及规划器仍默认关闭。具体阈值与 API 由各模块设置控制。

0.2.12 重新运行了 API 设置、板块开关、世界“更多”、剧情设置、总览、世界总览和世界管理的离线浏览器截图检查；楼尾总结与扩展面板沿用 0.2.11 的检查，地图设置沿用 0.2.10 的检查。没有重新运行真实模型联调。宿主静态导入与资源校验使用本地固定的 SillyTavern 1.19.0 源码；1.14.0／1.18.0 的部分真实保存函数用于自动测试。没有向用户正在使用的酒馆目录部署，也没有调用付费模型。**尚未完成实际酒馆浏览器及真实模型对话联调，不将本包标为稳定版。** 其他 Tavern 框架需另行验证适配。

## 数据与共存

扩展设置使用 `TavernKitchen`，记忆 IndexedDB 使用 `TavernKitchen_Memory`，后厨文件使用 `TavernKitchen_*`，OS 聊天引用与记忆本地配置也分开命名。不会自动迁移或删除旧小白X的设置、摘要或世界文件。

## 开发

需要 Node.js 24 与 pnpm 11.25.0。本次环境的系统 npm 安装不完整，因此改用 pnpm，并提交 `pnpm-lock.yaml`；没有修改系统 npm 或 Git 配置。

```sh
pnpm install --frozen-lockfile --ignore-scripts
pnpm build
pnpm test
pnpm check
python scripts/package.py
```

`build` 执行静态检查、类型检查、打包和宿主资源验证；`check` 还核对版本一致性、构建一致性、回归测试和记忆运行时。首次验证历史宿主保存函数可能下载固定提交；完整外层参考库可供离线宿主接口检查。构建过程不修改宿主源码。

测试结论及限制见 [验证记录](docs/VALIDATION.md)，发布步骤见 [发布流程](docs/RELEASING.md)。运行产物在 `dist/`，开发缓存和日志在 `output/`，安装 ZIP 在 `release/`。
