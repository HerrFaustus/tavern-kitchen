# 酒馆后厨 0.2.5

0.2.5 新增独立一级“总览”，位于世界之前，汇集当前场景、故事时钟、在场人物、计划、悬念、局面和重要剧情／世界状态。人物页增加认知与在场度，楼尾摘要增加来源明确的变化清单；新数据复用已有总结调用、保存、回退、导入导出与维护助手。下次成功总结后开始填充。见[总览与场景进展说明](docs/STORY-OVERVIEW.md)。

**Based on LittleWhiteBox by biex.** 本项目基于 [小白X](https://github.com/RT15548/LittleWhiteBox) 固定提交 `e30ebadf69cd53e9fafc5f81f74b9499911f78f5`（上游版本 3.2.2）删减而来。

当前仍基于删减底板演进：保留记忆、召回、剧情规划、变量、地图、世界后台和骰子，删除娱乐与表现功能及对应依赖。完整的“酒馆后厨”世界内核仍按外层项目的架构文档逐步实现。

## 本版保留什么

| 能力 | 当前实现 |
| --- | --- |
| 剧情 | 小白X剧情总结、分层记忆、人物与事件记录、维护与备份 |
| 召回 | 关键词检索、向量检索及召回上下文组装；Embedding 需要自行配置 |
| 规划 | 独立 ENA 规划器及上下文参考；尚非多作家编剧室 |
| 变量 | 原有变量指令、变量面板、更新与回滚；尚非内部化 MVU |
| 地图 | 层级地点、场景编辑、Three.js 三维场景与上下文投影 |
| 世界档案 | 独立实体身份、事实与候选、来源映射、事件提交、交易、历史分支及导入导出；旧模块仍逐步接入 |
| 后台世界 | 原有世界分区、背景维护与注入 |
| 骰子 | 原有行动检定与低概率遭遇；删除付费重掷与钱包依赖，重置人物属性不收费 |
| 基础设施 | 宿主桥接、API 预设、后台任务协调、确认写入、聊天分支与保存恢复 |

扩展入口先创建按钮和面板框架，再加载设置与功能，不等待模块初始化；首次打开进入“总览”。工具栏晚到或被重建时恢复同一入口。所有后厨页面固定跟随酒馆配色、字体、透明度与动效，不再提供独立主题选择；旧后厨主题选择不再生效。宿主决定扩展脚本加载时点，因此无法承诺与原生 HTML 按钮在同一帧出现。

内置教程、使用说明页和部署指南已移除。内页按钮、输入框、复选框与分组标题统一采用酒馆原生控件外观；规划页使用顶部按钮导航，保留必要的字段说明和操作状态。

顶部入口顺序为 **用户管理 → 后厨 → 角色管理**，后厨使用酒馆自带的实心门形图标。面板沿用原生右侧栏位置，桌面贴顶并自上而下展开，窄屏从工具栏下方展开；无展开工作区按钮。标题、导航使用原生控件，背景、透明度和模糊由宿主面板统一承担。一级导航为 **总览／世界／剧情／规划／设置**：世界下分别提供世界状态、局势、设定、人物、变量、地图和后台演化。人物页保留档案与关系图，并展示认知与在场度；局势页同时展示结构化局面与旧事实分组。旧关系链接仍进入人物页。见[工作台说明](docs/WORKSPACE-UI.md)。

角色回复下方会附上可展开、收起的总结，并提供“查看记忆”入口。直接展示已保存摘要，不增加模型调用；一个摘要覆盖多楼时明确标注区间。尚未总结或旧数据没有可核实的楼层归属时显示对应提示，不推测单楼内容。

0.2.4 将模型接口统一为命名 API 配置库，剧情、规划、世界／地图和召回各自选择配置。支持复制酒馆主接口或只复制连接后另选模型；旧设置自动迁移。详见[配置说明](docs/api-profiles.md)。

0.2.3 从源码与安装产物中移除旧手机桌面、快捷启动器、状态栏、底部导航、壁纸、桌面排序和装饰资源。世界工具只支持工作台内嵌，保留页面内部返回、加载与故障重试。详见[删除清单](docs/removed-phone-files.json)。

## 世界状态与总览 0.2.1

**世界就是整个世界状态的入口。** **世界 → 世界状态**（原总览）汇总对象、已确认状态、待处理记录数量与近期变化，不保存第二份档案，也不独立调用模型。人物、局势、设定、变量与地图是这个世界的分类视图，后台演化是它的运行机制。0.2.5 的一级总览同时读取剧情和世界，是跨栏目汇总视图。

新增、修订、来源确认、交易与分支备份集中在 **设置 → 世界管理**。总览和世界管理读取同一份内核状态；原“档案”独立导航已移除，旧链接转到总览。分类页仍在逐步接入统一内核，本版没有将旧存储全部迁移。

已有剧情记录和地图对象在打开总览或世界管理时同步，之后响应原模块的数据通知；不增加模型调用。明确且唯一的名称／别名可以绑定同一身份，歧义对象不自动合并。

来源记录先列为待处理项，确认后才成为当前事实；传闻、认知、计划和创作候选单独保留。可新增对象、编辑名称、登记状态、追溯来源与变更，关联对象可以点开查看。交易同时更新双方金币和物品归属，持有物品列表从归属推导。

存档保存在当前浏览器／应用的 IndexedDB，按角色或群组与聊天身份隔离。存档管理支持完整导出、恢复到新分支与分支切换；历史记录可以从指定版本建立新分支。**这还不是跨设备服务端存档，也不自动跟随宿主聊天回退。**

档案修改暂不回写旧地图和变量，也不作为新上下文注入；世界书仍由宿主读取。没有自动执行金币交易或替代旧骰子判定。完整边界见 [世界状态设计](docs/WORLD-ARCHIVE.md)。

## 已删除

绘图提供方及绘图服务端、语音、短信联系人与手机社交、钱包／银行／商店、小游戏、学习与奖励、第四墙、通用助手、电子书、独立酒馆界面、模板编辑器、沉浸模式、按钮折叠装饰、上游自动更新。混有短信与联系人逻辑的“小白板／小本本”整块移除，剧情规划由独立 ENA 模块承担。

删除包含源码、应用注册、构建入口、设置入口及无用依赖；不是仅把开关设为关闭。纯文本图片／语音标记解析器移到 `shared/legacy-markup`，用于导入旧聊天时清洗记忆，没有保留生成图片或播放语音能力。底层流式生成适配器供记忆与规划调用酒馆 API 使用。

[删除清单](docs/v1-removed-files.json)与[来源和修改说明](docs/UPSTREAM.md)可供核对。未经修改的小白X完整快照仍在外层项目的 `references/sources/RT15548__LittleWhiteBox`。

## 安装与开始

1. 在 SillyTavern 的“扩展”页面点击“安装扩展”，粘贴 `https://github.com/HerrFaustus/tavern-kitchen` 并安装。
2. 仓库已包含 `dist/` 构建产物，安装时无需运行 Node 或 pnpm；后续通过酒馆的扩展更新功能获取更新。
3. 刷新酒馆，点击顶部菜单栏的后厨门形图标。扩展设置里也保留“打开酒馆后厨”入口。也可下载仓库 ZIP，把完整目录以 `tavern-kitchen` 为名放到 `public/scripts/extensions/third-party/` 下。
4. 在“设置 → 功能开关”启用需要的板块并保存刷新。“设置 → 剧情设置”配置摘要和向量渠道，“设置 → 模型接口”配置世界相关模块的共享渠道；“规划 → 剧情规划”配置规划器。再按需启用地图维护、世界后台或骰子。

记忆和变量的消息快捷按钮也会打开对应标签，不再另起独立主面板。收起工作台再打开会回到上次标签；切换聊天会收起，避免把旧聊天视图误认成当前聊天。摘要自动触发、向量、地图自动维护、世界后台与骰子自动检定默认关闭，规划器也默认关闭。具体阈值与 API 由各模块设置控制。

本次没有向用户正在使用的酒馆目录部署，也没有调用付费模型。已完成离线浏览器工作台测试和桌面／窄屏截图检查，夹具代替了宿主接口和关系图依赖。宿主静态导入与资源校验使用本地固定的 SillyTavern 1.19.0 源码；1.14.0／1.18.0 的部分真实保存函数用于自动测试。**尚未完成实际酒馆浏览器及真实模型对话联调，不将本包标为稳定版。** 其他 Tavern 框架需另行验证适配。

## 数据与共存

扩展设置使用 `TavernKitchen`，记忆 IndexedDB 使用 `TavernKitchen_Memory`，后厨文件使用 `TavernKitchen_*`，OS 聊天引用与记忆本地配置也分开命名。不会自动迁移或删除旧小白X的设置、摘要或世界文件。

变量模块仍读写酒馆的局部／全局变量，部分旧指令仍沿用原语法。第一版未完成多插件共存验证；使用同一聊天时，请只让一个插件负责摘要隐藏、变量更新和规划注入。不要把本版视为已经接管世界书或 MVU：世界书依然按宿主规则参与上下文。

## 开发

需要 Node.js 24 与 pnpm 11.25.0。本次环境的系统 npm 安装不完整，因此改用 pnpm，并提交 `pnpm-lock.yaml`；没有修改系统 npm 或 Git 配置。

```sh
pnpm install --frozen-lockfile --ignore-scripts
pnpm build
pnpm test
pnpm check
python scripts/package.py
```

`build` 执行静态检查、类型检查、打包和宿主资源验证；`check` 还核对构建一致性、回归测试和记忆运行时。首次验证历史宿主保存函数可能下载固定提交；完整外层参考库可供离线宿主接口检查。构建过程不修改宿主源码。

测试结论及限制见 [验证记录](docs/VALIDATION.md)。运行产物在 `dist/`，开发缓存和日志在 `output/`，安装 ZIP 在 `release/`。
